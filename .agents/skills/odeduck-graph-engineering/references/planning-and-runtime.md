# 탐색 설계와 실행 지침

경로는 저장소 루트 기준입니다. 현재 변경과 관련된 절만 적용합니다.

## 개발 지침과 제품 실행을 구분한다

이 스킬은 개발 에이전트의 작업 지침이다. 제품 에이전트의 탐색·재계획 행동을 바꾸는 작업에서는
실제 입력을 추적한다. CLI 계획기와 MCP guide가 공유하는 실행 지침은
`internal/goalwork/planning-brief.md`이며 상세 계약은 `planning-guide.md`의 topic으로 나눈다.
기본 안내와 요청한 상세 topic만 두 경로에 전달한다.
관련 지침을 바꿀 때는 해당 action의 실행 계약·권한과 두 경로의 전달 테스트를 함께 확인한다.
지침 전달, 모델의 실제 선택, 최종 산출물의 정확도는 별도의 검증 결과다.

제품 실증 전에는 실행 중인 CLI/MCP의 build·노출 도구·실제 전달 지침과 카탈로그 revision을 확인한다.
저장소 HEAD나 최신 릴리스가 설치된 서버와 같다고 가정하지 않는다. 버전·권한·도구 제한으로 실행하지
않은 기능은 평가 범위에서 제외하고, host의 별도 코드·수작업 보완과 제품 실행 결과를 구분한다.

스킬을 갱신할 때는 실제로 잘못된 판단을 이끈 지침이나 호출 조건부터 찾는다. 개발 판단의 문제는
이 스킬의 해당 규칙을 고치고, 제품 계획기의 입력·행동 문제는 실행 지침에서, 구현 결함은 실행 계약과
회귀 테스트에서 다룬다. 한 번의 실패에 대한 새 금지 규칙을 쌓기보다 기존 규칙을 수정하거나 합친다.
구체적인 원천·정답·실패 기록은 평가 자료에 보존하고, 스킬에는 다른 목표에도 필요한 판단 기준만 남긴다.

스킬 갱신 요청은 영향받는 개발 지침과 호출 조건을 정리하는 것으로 마친다. 제품 지침·실행 코드의
변경은 그 요청에 포함된 경우에만 진행하고, 남은 제품 검증은 기존 실행·검증 계획에 유지한다.

## 실패 위치에서 다음 변경을 고른다

미완료 결과에서 먼저 `Discovery Gap`을 특정한다. 원래 목표 해석, 후보 발견, 실제 취득, 근거 전달,
연결·계산, 결과 검토 중 어디에서 필요한 정보나 행동이 끊겼는지 실제 요청·응답으로 확인한다.
이미 가능한 행동을 계획기가 선택하지 않은 경우와 실행기가 그 행동을 지원하지 않는 경우를 구분한다.
전자는 기존 도구의 노출·입력·실행 지침을, 후자는 해당 실행 계약을 조사한다. 새 도구나 저장소의
필요성은 이 격차에서 설명하며, 모델의 보류 자체를 기능 요구사항으로 삼지 않는다.

다음 변경에는 같은 목표에서 달라져야 할 관찰 결과를 붙인다. 근거가 이미 전달됐다면 원문에 대한
주장 강도와 적용 범위를 대조하고, 판정만 달라졌다면 입력 차이와 독립 기대값을 확인한다. 이 판단에
필요한 근거가 없으면 취득·진단부터 진행한다.

## 질문을 먼저 고정한다

이미 고정한 대표 질문과 기대 결과를 재사용한다. 새 범용 설계에서는 서로 다른 분야와 산출물을
포함하도록 질문을 고른다. 각 질문에 시작점, 탐색 경로, 필요한 시간 범위, 허용 가능한 오탐을 붙인다.
국소 변경마다 질문 목록을 새로 만들거나, 현재 구현에 맞춰 기존 질문의 범위·역할을 줄이지 않는다.

설계 판단은 각 질문이 산출물 또는 고객 행동으로 이어지고, 표나 검색 색인만으로 충분한지까지
설명해야 한다. 이는 제품 완주의 증거와 별개다. 경로 탐색이 핵심이 아니면 그래프 DB를 선택하지 않는다.

### 발견과 연결 검증을 따로 설계한다

목표에 필요한 관측 역할에서 후보를 찾는다. 의미적으로 가까운 자료뿐 아니라 부족한 측정값·비교 대상·
중간 대응표를 채우는 자료를 탐색하고, 실제 검사에서 드러난 빈 역할을 다음 검색에 반영한다.
공공데이터 실증에는 오데덕의 검색·검사·취득 경로를 사용한다. 웹의 공식 방법론 조사는 이 실증과 구분한다.

온톨로지나 어휘 사전은 개념·대체 표기·탐색 관계를 정리할 때 사용한다. 원천 필드의 의미·단위·관측
단위·식별 namespace로의 매핑은 원천과 revision에 묶인 별도 근거다. 개념의 유사/상하 관계가 실제
대상의 동일성을 승인하지 않는다. 적용안 비교가 필요하면 `docs/agents/harness-sources.md`의
방법론 검토로 들어가 해당 결정의 채택·유보 이유를 읽는다. 특정 원천의 정답 경로는 평가 자료에 둔다.
