# 실행 구조와 저장소 선택

경로는 저장소 루트 기준입니다. 현재 변경과 관련된 절만 적용합니다.

## 저장 기술은 마지막에 고른다

취득·선택 한도를 이유로 실행 구조를 넓히기 전에, 검사한 공식 계약이 제공하는 기간·지역·항목 선택으로
원래 질문을 충족할 수 있는지 확인한다. 선택 기능의 존재뿐 아니라 실제 반환 범위·필드·완전성을
검증한다. 요청 조건과 반환 범위가 다를 수 있으므로 원천에서 선택한 조건과 로컬 `Sample Selection`을
따로 남긴다. 지원되지 않는 선택이나 질문의 일부만 남기는 축소는 이 대안의 성공이 아니다.

공식 계약의 특수성은 원천 adapter에, 여러 원천에서 같은 의미로 필요한 계산·검증은 공통 실행기에
둔다. 기존 경로 재사용·작은 adapter·공통 계약 확장을 비교하되 가상의 후속 원천을 위해 framework를
먼저 만들지 않는다. 원천별 URL·필드 규칙은 계약과 fixture에 두고, 특정 질문의 정답 경로는 평가에 둔다.
범용성 검증은 [평가 기준](evaluation.md)을 따른다.

다음 중 실제로 필요한 능력으로 선택을 설명한다.

- key lookup과 bounded join만 필요: 기존 저장소·색인 유지
- 반복적인 가변 길이 경로와 관계 중심 질의: property graph 후보
- 공개 표준 vocabulary와 외부 의미 호환: RDF 계열 후보
- 사건 재현과 정정 순서가 핵심: append-only event/claim store 후보

선택이 어렵게 되돌릴 수 있고 놀라우며 실제 trade-off가 있을 때만 ADR을 쓴다. 기술을 선택했다는 이유로
도메인 계약을 그 기술의 node/label 문법으로 축소하지 않는다.

새 계층을 구현하거나 기존 계층을 유지하는 이유를 [평가 기준](evaluation.md)의 기준선에서 남는 구체적 실패와 연결한다.
먼저 기존 도구·질의·지침으로 해결 가능한지 확인하고, 추가 구성으로 달라져야 할 산출물·오탐·비용을
고정한다. 동등한 목표 충족과 안전성을 더 단순하게 달성하면 축소·선택 기능화·제거를 우선 검토한다.
미측정 효용은 가설로 남기며 기술 도입·코드량·테스트 통과를 사용자 가치로 대신하지 않는다.
권한·인증·근거 보존 장치의 필요성은 관련 위험 회귀로 별도 검증한다. 한 번의 검색 동률을 그 장치의
불필요함이나 제품 전체의 무가치함으로 해석하지 않는다.

구조를 교체할 때는 대체할 호출 경로·중복 규칙·활성 문서를 함께 식별한다. 호출자와 호환 계약을
검증한 뒤 낡은 경로를 제거하거나 단일 기준을 가리키게 한다. 과거 실패 근거와 정정 이력은 지우지 않는다.

## 결과 형식

기존 문서의 해당 부분을 갱신한다. 국소 변경에 무관한 항목을 다시 작성하거나 별도 보고서를 복제하지 않는다.

1. 영향받는 대표 질문·기대 산출물·허용 오탐
2. entity, record, claim/event 사전
3. 식별자와 match 등급 표
4. edge별 provenance·시간 계약
5. 불확실성·정정·coverage 표현
6. gold set·행동별 통과선과 실제 양성 완주 증거 또는 남은 격차
7. 저장 선택 또는 현 구조 유지 결정

문서 변경이 요청 범위에 있을 때 확정된 용어를 `CONTEXT.md`에 구현 세부 없이 반영하고, 되돌리기
어려운 저장·식별 결정만 `docs/adr/`에 남긴다. 읽기 전용 검토에서는 수정 제안만 보고한다.
설계 참고 자료는 `docs/agents/harness-sources.md`에 기록돼 있으며 실행에는 외부 스킬이나 그래프
제품이 필요하지 않다.
