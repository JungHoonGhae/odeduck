# 연결·검색·목표 완주 평가

경로는 저장소 루트 기준입니다. 현재 변경과 관련된 절만 적용합니다.

## gold set으로 검증한다

실제 원천 record에서 구현의 출력과 독립적으로 기대 결과를 정한다. 기존 평가셋을 재사용하고 변경에
필요한 사례만 보강한다. 고정된 프로젝트 평가 계약은 유지하되, 새 평가 사례는 해당 질문의 연결 위험에서
고른다. 다음 위험을 그 도메인의 실제 대상과 관계로 구체화한다.

- 명백한 동일 대상과 중복 record
- 이름은 같지만 다른 hard negative
- 식별자·속성·소속·관측 범위가 바뀐 temporal case
- 서로 다른 관측 단위나 전체·부분을 혼동하기 쉬운 case
- 정정·취소·삭제된 사건
- 식별자가 없어 unresolved로 남아야 하는 case

사업체·브랜드 같은 특정 도메인 사례를 모든 분석의 필수 조건으로 이식하지 않는다. 국소 변경에서는
영향받는 위험과 기존 회귀를 검증하고, 범용성을 주장할 때 설계에 쓰지 않은 분야로 전이를 확인한다.

precision과 recall을 전체 평균만으로 보고하지 않는다. match 등급과 고객 행동별로 나눈다. 자동 신청,
판매 중지, 위험 경보처럼 행동 비용이 큰 경로는 별도의 precision 통과선을 정하고, 미달하면 사람 검토로
보낸다.

연결 판정 평가와 목표 완주 평가는 별도로 보고한다. 가능한 양성 목표가 실제 CLI/MCP 공통 실행에서
결과에 도달하는지 확인한다. 모든 사례가 검토·거절로 끝나거나 fake runner가 성공 상태를 주입한
테스트만 통과한 상태는 완주가 아니다. 특정 dataset ID로 정답을 안내하지 말고, 이미 개발에 쓴 원천과
미노출 평가를 구분한다. 구체적인 반복 횟수·통과선은 프로젝트의 평가 계약에만 둔다.

근거 전달을 최적화할 때는 수신자가 실제 받는 직렬화된 전체 입력을 측정한다. 선택한 원문뿐 아니라
원천·변환·비교·적용 범위 메타데이터를 포함해 적용되는 개수·크기·호출 한도를 각각 확인한다. 중복을
줄인 뒤에도 같은 주장과 출처, 미대응 기록을 재현할 수 있어야 한다. 한 단계의 한도 통과와 최종
전달·검토 성공은 구분하며, 구체적인 수치와 실패 입력은 해당 실행 계약·평가 자료에 남긴다.

검색·구조 개선의 기준선은 같은 AI가 키워드를 만들고 검색·검사·원본 분석·후속 탐색을 할 수 있는
가장 단순한 허용 경로다. 모호한 사용자 문장을 그대로 넣는 lexical 검색만으로 제품 차별성을 평가하지
않는다. 병렬화나 맥락의 기여를 주장하면 같은 최초 요청에서 결과를 공유하지 않는 독립 검색과도
비교한다. 같은 목표·카탈로그·모델·권한·예산에서 바꾼 요소와 실패를 남기고 기대 결과는 고정한다.

의미 검색 실사용, 후보 추가 회수, 실제 연결·계산, 최종 목표 충족을 따로 기록한다. 전체 경로를
실행하지 않은 비교는 해당 단계의 진단이다. 검색어·PK를 알려준 재생, 평가 대상과 공유한 검사기,
host의 별도 분석, 단일 목표·단일 실행의 한계를 밝히고 제품 전체나 경쟁사 우열로 확대하지 않는다.
초기 색인 구축·갱신, 요청별 시간·모델 사용량, 운영 의존성과 오탐 비용을 분리한다. 개발·비교 판단에
필요한 검증이며 일반 사용자 요청마다 대조 실험을 실행하라는 뜻은 아니다.

모델 검토를 쓰면 모델의 판정과 독립 원천에 대조한 정확도를 따로 기록한다. 검토자의 승인만으로 목표
달성을 판정하지 않는다. 원천 revision이 바뀌면 이전 실패와 기대값을 보존한 별도 평가로 다룬다.
