# 식별·근거·시간·결합 계약

경로는 저장소 루트 기준입니다. 현재 변경과 관련된 절만 적용합니다.

## 네 층을 분리한다

| 층 | 역할 | 안정 키 |
| --- | --- | --- |
| Source | 데이터셋과 제공기관의 계약 | provider + dataset ID + revision |
| Record | 원천이 실제로 준 행·문서·응답 | source + record ID 또는 content hash |
| Entity | 여러 record가 가리킬 수 있는 실제 대상 | 오데덕 내부 canonical ID |
| Claim/Event | 누가 무엇을 언제 주장하거나 관찰했는지 | source record + relation + time |

이 표는 의미와 책임의 경계이며, 층마다 별도 클래스·테이블·그래프 node를 만들라는 지시가 아니다.
필요한 구분을 기존 record와 provenance 필드로 보존할 수 있다면 그 구조를 유지한다.

원천 값을 canonical entity에 덮어쓰지 않는다. 속성별 survivorship 규칙과 원천별 값을 함께 보존한다.
사건, n항 관계, 시간에 따라 바뀌는 관계는 독립적으로 조회해야 하므로 node 또는 동등한 1급 record로
표현한다.

## 식별 계약을 쓴다

연결마다 다음 중 하나를 붙인다.

1. `exact`: 발급·관리기관과 적용 범위가 일치하는 안정 식별자
2. `deterministic`: 둘 이상의 필드와 정규화 규칙이 모두 맞는 재현 가능한 규칙
3. `probabilistic`: 점수와 근거가 있는 후보 연결
4. `unresolved`: 후보는 있으나 확정할 수 없음

이름만 같은 연결은 `probabilistic` 이상으로 승격하지 않는다. 식별자의 발급기관, 적용 범위, 재사용
가능성, 폐기·변경 규칙을 기록한다. downstream이 확률 연결을 사실처럼 소비하지 못하도록 상태를
계약에 포함한다.

## edge에 증거와 시간을 붙인다

각 edge 또는 claim에는 다음이 추적 가능해야 한다.

- 원천 dataset과 source record
- 추출한 원문 필드와 정규화 버전
- match 방법, confidence, 검토 상태
- `validFrom/validTo`: 현실에서 효력이 있었던 시간
- `observedAt`: 오데덕이 원천에서 본 시간
- 정정·삭제·대체된 claim과의 관계

공개일과 사건일을 섞지 않는다. 현재 원천에서 사라진 record도 이전 결정을 재현할 수 있도록 tombstone
또는 revision으로 남긴다. 원천 coverage 밖의 `미발견`은 부정 사실이 아니다.

근거 재사용을 설계할 때는 취득·관측 ID와 원문 식별을 구분한다. 서로 다른 관측이 같은 원문을
가리킨다는 판단에는 원천 revision·원문 위치·해석 계약과 값·누락 상태의 일치가 필요하다. 값이 같다는
이유만으로 근거를 합치지 않으며, 같은 원문 위치의 충돌은 보존하고 확인한다. 검증된 원문을 기존
공개 권한 안에서 참조로 재사용할 수 있는지 먼저 검토하고, 지원 범위와 한도는 실행 계약에 둔다.

원문 재사용은 대상의 동일성이나 주장의 적용 범위를 승인하지 않는다. 정의·주석·대응표는 원문
위치·revision·적용 범위를 주장과 검토 입력까지 연결한다. 같은 파일에 있다는 이유만으로 모든 행에
적용하지 않는다. 특정 원천의 날짜·필드·대응 정답은 실행 계약과 평가 자료에 둔다.

취득 범위는 파일 전체 검사, 조건에 일치한 행의 보관, 원천이 포괄하는 모집단으로 나눠 확인한다.
그 뒤 결합·시간 조건에서 제외된 기록을 원천 위치와 함께 추적한다. 전체 파일이나 모든 보유 행을
처리했다는 사실만으로 질문의 전체 범위를 충족하지 않는다. 비교 불가능한 부분을 요청받았다면
대응된 행만 보고하지 말고 미대응 기록과 그 해석에 필요한 근거를 드러낸다. 원문 공개는 기존 선택
권한을 유지하며, 보관 한도·평가 수치·특정 원천의 대응 규칙은 스킬 대신 해당 실행 계약에 둔다.

### 주장 강도와 목표 충족을 분리한다

- **원천 보고**: 특정 revision의 record에 필드·값·문구가 있다는 근거. 현실의 현재 상태를 보증하지 않는다.
- **계산 분석**: 원천 행, 변환, 단위·기간·모집단과 재현 가능한 계산. 산술 일치만으로 의미가 검증되지는 않는다.
- **근거 있는 가설**: 원천이 지지하는 전제, 추론, 남은 가정과 반증 방법. 추론을 관측 사실로 저장하지 않는다.

원천 추적 가능성, 주장에 대한 지지, 사용자 목표 충족을 하나의 confidence나 승인 값으로 합치지 않는다.
사용자가 원천 보고를 요구했는데 현재 안전성·인과 효과까지 완료 조건으로 추가하지 않는다. 반대로 강한
결론을 요구했으면 더 약한 원천 보고가 가능하다는 이유로 목표 전체를 완료 처리하지 않는다.
부족한 근거에 대해서는 같은 목표 안에서 추가 관측·중간 대응표·대안을 찾는 경로를 설계한다.
검토나 재계획을 열 때도 기존 예산, 근거 revision, 정정 이력과 공개 범위를 유지해야 한다.

### 결합 전에 관측 단위를 맞춘다

각 원천에서 한 행이 나타내는 대상·지역·기간과 연결 배수를 확인한다. 단위가 다르면 질문에 맞는
선집계나 대응 관계를 먼저 정하고, 결합 후 같은 기여를 반복 합산하지 않는지 독립 기대값으로 검증한다.
계산된 그룹은 제공기관의 원본 record와 구분하고, 모든 기여 record·변환·단위·기간을 추적 가능하게
유지한다. 일부 원본을 제외하면 그룹도 다시 계산해야 하며, 보유 표본의 집계를 모집단 전체로 확대하지 않는다.

## 관계의 의미를 좁힌다

node는 정체성이 있는 명사, edge는 방향이 있는 동사로 이름 짓는다. `RELATED_TO`, `HAS`, `Entity`,
`Thing`처럼 질문을 설명하지 못하는 이름은 사용하지 않는다. 관계 방향은 읽었을 때 문장이 되어야 한다.

초고차수 node가 될 국가, 상태, 카테고리, 날짜는 탐색 대상이 아니라면 속성이나 별도 색인으로 둔다.
한 node의 예상 fan-out과 검색 expansion budget을 기록하고, 무제한 전이 추론은 허용하지 않는다.

## 강제 탈락 패턴

- 제목이나 설명의 공통 단어를 영구 edge로 저장한다. 검색 유사도는 관계 증거가 아니다.
- 같은 상호·기관·제품명을 하나의 canonical node로 합친다. 이름은 후보 생성에만 쓴다.
- confidence 숫자만 남기고 source record와 match 방법을 버린다. 점수는 provenance를 대체하지 않는다.
- 최신 값을 canonical 속성에 덮어써 정정 전 판단을 재현하지 못하게 한다.
- graph UI가 보기 좋다는 이유로 graph database를 선택한다. 저장 선택은 고정 질의와 benchmark가 한다.
- 모든 edge를 전이시켜 간접 관계를 사실로 표현한다. relation별 허용된 경로만 탐색한다.
