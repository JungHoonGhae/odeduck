# 오데덕 그래프 엔지니어링

그래프 저장소를 고르기 전에 **어떤 질문에 어떤 증거로 답할지**를 고정한다. 같은 이름은 같은 대상이
아니며, 연결은 사실 자체가 아니라 특정 원천과 시점에서 관찰된 주장이다.

`INTENT.md`가 제품 목표의 기준이다. 검색 후보·안전한 거절·구조 개선만으로 완료를 대신하지 않는다.
연결을 사용해 사용자가 요구한 보고·계산·가설에 도달하는 경로까지 검토한다. 현재 구현 상태와
평가 계약은 `docs/specs/goal-driven-completion-plan.md` 및 거기서 연결한 관련 문서를 필요할 때 읽는다.
이 스킬은 실행 중인 제품의 승인 규칙을 바꾸거나 계획기의 의미 판단을 자동 승인할 권한이 아니다.

## 1. 질문을 먼저 고정한다

이미 고정한 대표 질문과 기대 결과를 재사용한다. 새 범용 설계에서는 서로 다른 분야와 산출물을
포함하도록 질문을 고른다. 각 질문에 시작점, 탐색 경로, 필요한 시간 범위, 허용 가능한 오탐을 붙인다.
국소 변경마다 질문 목록을 새로 만들거나, 현재 구현에 맞춰 기존 질문의 범위·역할을 줄이지 않는다.

설계 판단은 각 질문이 산출물 또는 고객 행동으로 이어지고, 표나 검색 색인만으로 충분한지까지
설명해야 한다. 이는 제품 완주의 증거와 별개다. 경로 탐색이 핵심이 아니면 그래프 DB를 선택하지 않는다.

### 발견과 연결 검증을 따로 설계한다

목표에 필요한 관측 역할에서 후보를 찾는다. 의미적으로 가까운 자료뿐 아니라 부족한 측정값·비교 대상·
중간 대응표를 채우는 자료를 탐색하고, 실제 검사에서 드러난 빈 역할을 다음 검색에 반영한다.
공공데이터 실증에는 오데덕의 검색·검사·취득 경로를 사용한다. 웹의 공식 방법론 조사는 이 실증과 구분한다.

온톨로지나 어휘 사전은 개념·대체 표기·탐색 관계를 정리할 때 사용한다. 원천 필드의 의미·단위·관측
단위·식별 namespace로의 매핑은 원천과 revision에 묶인 별도 근거다. 개념의 유사/상하 관계가 실제
대상의 동일성을 승인하지 않는다. 적용안 비교가 필요하면 `docs/agents/harness-sources.md`의
방법론 검토로 들어가 해당 결정의 채택·유보 이유를 읽는다. 특정 원천의 정답 경로는 평가 자료에 둔다.

## 2. 네 층을 분리한다

| 층 | 역할 | 안정 키 |
| --- | --- | --- |
| Source | 데이터셋과 제공기관의 계약 | provider + dataset ID + revision |
| Record | 원천이 실제로 준 행·문서·응답 | source + record ID 또는 content hash |
| Entity | 여러 record가 가리킬 수 있는 실제 대상 | 오대덕 내부 canonical ID |
| Claim/Event | 누가 무엇을 언제 주장하거나 관찰했는지 | source record + relation + time |

이 표는 의미와 책임의 경계이며, 층마다 별도 클래스·테이블·그래프 node를 만들라는 지시가 아니다.
필요한 구분을 기존 record와 provenance 필드로 보존할 수 있다면 그 구조를 유지한다.

원천 값을 canonical entity에 덮어쓰지 않는다. 속성별 survivorship 규칙과 원천별 값을 함께 보존한다.
사건, n항 관계, 시간에 따라 바뀌는 관계는 독립적으로 조회해야 하므로 node 또는 동등한 1급 record로
표현한다.

## 3. 식별 계약을 쓴다

연결마다 다음 중 하나를 붙인다.

1. `exact`: 발급·관리기관과 적용 범위가 일치하는 안정 식별자
2. `deterministic`: 둘 이상의 필드와 정규화 규칙이 모두 맞는 재현 가능한 규칙
3. `probabilistic`: 점수와 근거가 있는 후보 연결
4. `unresolved`: 후보는 있으나 확정할 수 없음

이름만 같은 연결은 `probabilistic` 이상으로 승격하지 않는다. 식별자의 발급기관, 적용 범위, 재사용
가능성, 폐기·변경 규칙을 기록한다. downstream이 확률 연결을 사실처럼 소비하지 못하도록 상태를
계약에 포함한다.

## 4. edge에 증거와 시간을 붙인다

각 edge 또는 claim에는 다음이 추적 가능해야 한다.

- 원천 dataset과 source record
- 추출한 원문 필드와 정규화 버전
- match 방법, confidence, 검토 상태
- `validFrom/validTo`: 현실에서 효력이 있었던 시간
- `observedAt`: 오대덕이 원천에서 본 시간
- 정정·삭제·대체된 claim과의 관계

공개일과 사건일을 섞지 않는다. 현재 원천에서 사라진 record도 이전 결정을 재현할 수 있도록 tombstone
또는 revision으로 남긴다. 원천 coverage 밖의 `미발견`은 부정 사실이 아니다.

정의·주석·대응표는 원문 위치·revision·적용 범위를 주장과 검토 입력까지 연결한다. 같은 파일에 있다는
이유만으로 모든 행에 적용하지 않는다. 특정 원천의 날짜·필드·대응 정답은 실행 계약과 평가 자료에
두고, 스킬에는 다른 분야에도 적용할 검증 절차를 남긴다.

취득 범위는 파일 전체 검사, 조건에 일치한 행의 보관, 원천이 포괄하는 모집단으로 나눠 확인한다.
그 뒤 결합·시간 조건에서 제외된 기록을 원천 위치와 함께 추적한다. 전체 파일이나 모든 보유 행을
처리했다는 사실만으로 질문의 전체 범위를 충족하지 않는다. 비교 불가능한 부분을 요청받았다면
대응된 행만 보고하지 말고 미대응 기록과 그 해석에 필요한 근거를 드러낸다. 원문 공개는 기존 선택
권한을 유지하며, 보관 한도·평가 수치·특정 원천의 대응 규칙은 스킬 대신 해당 실행 계약에 둔다.

### 주장 강도와 목표 충족을 분리한다

- **원천 보고**: 특정 revision의 record에 필드·값·문구가 있다는 근거. 현실의 현재 상태를 보증하지 않는다.
- **계산 분석**: 원천 행, 변환, 단위·기간·모집단과 재현 가능한 계산. 산술 일치만으로 의미가 검증되지는 않는다.
- **근거 있는 가설**: 원천이 지지하는 전제, 추론, 남은 가정과 반증 방법. 추론을 관측 사실로 저장하지 않는다.

원천 추적 가능성, 주장에 대한 지지, 사용자 목표 충족을 하나의 confidence나 승인 값으로 합치지 않는다.
사용자가 원천 보고를 요구했는데 현재 안전성·인과 효과까지 완료 조건으로 추가하지 않는다. 반대로 강한
결론을 요구했으면 더 약한 원천 보고가 가능하다는 이유로 목표 전체를 완료 처리하지 않는다.
부족한 근거에 대해서는 같은 목표 안에서 추가 관측·중간 대응표·대안을 찾는 경로를 설계한다.
검토나 재계획을 열 때도 기존 예산, 근거 revision, 정정 이력과 공개 범위를 유지해야 한다.

### 결합 전에 관측 단위를 맞춘다

각 원천에서 한 행이 나타내는 대상·지역·기간과 연결 배수를 확인한다. 단위가 다르면 질문에 맞는
선집계나 대응 관계를 먼저 정하고, 결합 후 같은 기여를 반복 합산하지 않는지 독립 기대값으로 검증한다.
계산된 그룹은 제공기관의 원본 record와 구분하고, 모든 기여 record·변환·단위·기간을 추적 가능하게
유지한다. 일부 원본을 제외하면 그룹도 다시 계산해야 하며, 보유 표본의 집계를 모집단 전체로 확대하지 않는다.

## 5. 관계의 의미를 좁힌다

node는 정체성이 있는 명사, edge는 방향이 있는 동사로 이름 짓는다. `RELATED_TO`, `HAS`, `Entity`,
`Thing`처럼 질문을 설명하지 못하는 이름은 사용하지 않는다. 관계 방향은 읽었을 때 문장이 되어야 한다.

초고차수 node가 될 국가, 상태, 카테고리, 날짜는 탐색 대상이 아니라면 속성이나 별도 색인으로 둔다.
한 node의 예상 fan-out과 검색 expansion budget을 기록하고, 무제한 전이 추론은 허용하지 않는다.

## 6. gold set으로 검증한다

실제 원천 record에서 구현의 출력과 독립적으로 기대 결과를 정한다. 기존 평가셋을 재사용하고 변경에
필요한 사례만 보강한다. 고정된 프로젝트 평가 계약은 유지하되, 새 평가 사례는 해당 질문의 연결 위험에서
고른다. 다음 위험을 그 도메인의 실제 대상과 관계로 구체화한다.

- 명백한 동일 대상과 중복 record
- 이름은 같지만 다른 hard negative
- 식별자·속성·소속·관측 범위가 바뀐 temporal case
- 서로 다른 관측 단위나 전체·부분을 혼동하기 쉬운 case
- 정정·취소·삭제된 사건
- 식별자가 없어 unresolved로 남아야 하는 case

사업체·브랜드 같은 특정 도메인 사례를 모든 분석의 필수 조건으로 이식하지 않는다. 국소 변경에서는
영향받는 위험과 기존 회귀를 검증하고, 범용성을 주장할 때 설계에 쓰지 않은 분야로 전이를 확인한다.

precision과 recall을 전체 평균만으로 보고하지 않는다. match 등급과 고객 행동별로 나눈다. 자동 신청,
판매 중지, 위험 경보처럼 행동 비용이 큰 경로는 별도의 precision 통과선을 정하고, 미달하면 사람 검토로
보낸다.

연결 판정 평가와 목표 완주 평가는 별도로 보고한다. 가능한 양성 목표가 실제 CLI/MCP 공통 실행에서
결과에 도달하는지 확인한다. 모든 사례가 검토·거절로 끝나거나 fake runner가 성공 상태를 주입한
테스트만 통과한 상태는 완주가 아니다. 특정 dataset ID로 정답을 안내하지 말고, 이미 개발에 쓴 원천과
미노출 평가를 구분한다. 구체적인 반복 횟수·통과선은 프로젝트의 평가 계약에만 둔다.

검색 개선을 주장할 때는 같은 목표·카탈로그·모델·예산에서 어휘 검색 기준선과 비교한다. 의미 검색의
실사용, 필요한 후보의 추가 발견, 최종 목표 완주를 각각 기록하고 비용·오탐도 함께 본다. 사람이 준
검색어·PK로 원천을 재생한 실행은 진단이며 무힌트 자율 발견의 증거와 구분한다. 한 번에 바꾼 요소와
실패한 시도도 남기고, 같은 실험에서 정답·승인 기준을 변경하지 않는다.

모델 검토를 쓰면 모델의 판정과 독립 원천에 대조한 정확도를 따로 기록한다. 검토자의 승인만으로 목표
달성을 판정하지 않는다. 부족하다는 판정은 다음 취득이나 재계획의 근거이지 새 추상화를 추가할 이유
자체가 아니다. 판정이 바뀌면 바뀐 입력과 원천 근거를 대조하고, 원천 revision이 바뀌면 이전 실패와
기대값을 보존한 별도 평가로 다룬다.

## 7. 저장 기술은 마지막에 고른다

다음 중 실제로 필요한 능력으로 선택을 설명한다.

- key lookup과 bounded join만 필요: 기존 저장소·색인 유지
- 반복적인 가변 길이 경로와 관계 중심 질의: property graph 후보
- 공개 표준 vocabulary와 외부 의미 호환: RDF 계열 후보
- 사건 재현과 정정 순서가 핵심: append-only event/claim store 후보

선택이 어렵게 되돌릴 수 있고 놀라우며 실제 trade-off가 있을 때만 ADR을 쓴다. 기술을 선택했다는 이유로
도메인 계약을 그 기술의 node/label 문법으로 축소하지 않는다.

구조를 교체할 때는 대체할 호출 경로·중복 규칙·활성 문서를 함께 식별한다. 호출자와 호환 계약을
검증한 뒤 낡은 경로를 제거하거나 단일 기준을 가리키게 한다. 과거 실패 근거와 정정 이력은 지우지 않는다.

## 강제 탈락 패턴

- 제목이나 설명의 공통 단어를 영구 edge로 저장한다. 검색 유사도는 관계 증거가 아니다.
- 같은 상호·기관·제품명을 하나의 canonical node로 합친다. 이름은 후보 생성에만 쓴다.
- confidence 숫자만 남기고 source record와 match 방법을 버린다. 점수는 provenance를 대체하지 않는다.
- 최신 값을 canonical 속성에 덮어써 정정 전 판단을 재현하지 못하게 한다.
- graph UI가 보기 좋다는 이유로 graph database를 선택한다. 저장 선택은 고정 질의와 benchmark가 한다.
- 모든 edge를 전이시켜 간접 관계를 사실로 표현한다. relation별 허용된 경로만 탐색한다.

## 결과 형식

기존 문서의 해당 부분을 갱신한다. 국소 변경에 무관한 항목을 다시 작성하거나 별도 보고서를 복제하지 않는다.

1. 영향받는 대표 질문·기대 산출물·허용 오탐
2. entity, record, claim/event 사전
3. 식별자와 match 등급 표
4. edge별 provenance·시간 계약
5. 불확실성·정정·coverage 표현
