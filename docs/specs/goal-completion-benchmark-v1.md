## Execution order

1. Preserve the five questions below before changing production planning, acquisition or acceptance.
2. Inspect official source contracts and acquire reference records independently of `solve`. Record exact
   URLs, observation time, content hash, selected asset/sheet/rows, licence and unresolved meanings.
3. Freeze expected output values, included/excluded record pairs, units, temporal interpretation and
   coverage from those records. The oracle must not be generated by the executor under evaluation.
4. Only then implement against that case. Run scripted execution and unseeded discovery separately.
5. Evaluate all frozen cases, including held-out records. A changed source creates a new oracle revision;
   preserve the previous result. A failed implementation never justifies weakening the question.

Completion of step 3 requires independently checked positive outputs AND hard negatives for every case.
Source existence, schema inspection and hashes alone do not complete it. If an essential source is absent,
record the dependency and continue other cases; keep the original case on the completion gate.

### G1 — welfare / heat response

Question: 폭염 때 어르신들이 쉴 곳을 찾는 데 도움이 되는 서로 다른 공공데이터를 연결해 표본 비교표를
보여줘. 전국 단위이며 지역과 연도 해석의 한계를 명시해줘.

- Start/path: need for shelter → elderly population → administrative/legal crosswalk where needed → shelter supply.
- Product: a multi-region sample comparison with unambiguous region identity, elderly count, shelter name,
  location and source reference periods. Show which regions the sample covers; a single selected municipality
  does not establish the requested nationwide scope or representativeness.
- Time: retain source reference periods and actual operation intervals separately. Unknown current operation
  cannot become a recommendation to visit now. Quantitative cross-period comparison requires an explicit policy.
- Hard negatives: Kimcheon/Yeosu Nam-myeon collision; administrative vs legal area; duplicated population
  after 1:N joins; 2019 operation interpreted as current. Preserve existing failures as regression evidence.

### G2 — public facilities / mobility

Question: 인천의 공공 문화·관광시설을 휠체어 이용자가 비교할 수 있게, 시설의 접근성 정보와 주변
대중교통 정보를 연결해 표를 만들어줘. 자료별 기준일과 실제 이동 가능 여부를 확인하지 못한 부분도 보여줘.

- Start/path: usable facility → accessibility observations → facility location → nearby transit locations.
- Product: facility identity/address, observed accessibility attributes, nearby stops, reproducible distance
  definition and value, each source date, and a separate statement of what remains unknown about the route.
- Time: compare declared snapshots, not a claim of present operation. Changed or closed facilities retain status.
- Hard negatives: same-name facilities at different addresses; missing ramp data interpreted as absence;
  geographic proximity interpreted as a wheelchair-traversable route; wrong coordinate system or swapped axes.
- Distance is a geographic comparison, not proof of walking access. If actual route accessibility is requested
  in a later user goal, the system must acquire it or mark that requirement incomplete rather than reuse this scope.

### G3 — environment / geography

Question: 2024년 지역별 대기 관측값을 측정소 위치와 함께 비교할 수 있게 표로 보여줘. 관측 지점과
지역 통계의 차이, 단위, 결측 처리와 지역 내 관측 범위를 구분해줘.

- Start/path: regional observations → station/measurement-network identity → locations → regional grouping.
- Product: region, measurement period, pollutant, unit, value, aggregation level and corresponding station
  locations/coverage. A regional aggregate must remain a regional aggregate, not a per-station measurement.
- Time: 2024 observations and a compatible station revision; relocation and network changes require evidence.
- Hard negatives: city and province aggregates mixed; station counts joined as concentrations; sentinel -999
  used as a measured value; group totals duplicated across station rows; observation inferred outside coverage.

### G4 — education / demographics

Question: 인천의 지역별 학령인구와 학교 규모를 연결해 비교표를 만들어줘. 학령인구는 만 6~17세로
구분하고, 인구 기준일과 학교 기준일, 행정구역 개편으로 비교할 수 없는 부분을 명시해줘.

- Start/path: ages 6–17 → population by compatible area → historical area mapping → school enrolment/size.
- Product: area identity/version, ages 6–17 count, school count, enrolled student count and source reference
  dates. Enrolment is distinct from resident school-age population; neither is automatically school capacity.
- Time: retain the population date and the school census date. A 2026-07-01 area label must not be treated as
  the effective area of the 2026-04-01 census without an official historical correspondence.
- Hard negatives: 0–9 or 10–19 age bands substituted for 6–17; enrolment counted as capacity; totals plus their
  component grades counted twice; future and old districts equated; aggregated tables mixed with school records.

### G5 — product identity / certification / recall events

Question: 같은 제품에 관한 인증 정보와 회수 사건을 찾아 연결한 사례를 보여줘. 인증번호·모델·변형과
사건 날짜를 근거로 무엇이 같은 제품인지, 확인되지 않은 것은 무엇인지 구분해줘.

- Start/path: product → scoped certification identity → model/variant → recall event and event detail.
- Product: certification identity/status, model/variant, matched recall ID/date, exact source records and
  match method. Certification and recall may be different operations of the same dataset; dataset-count
  alone is not a measure of cross-domain discovery. Other cases must establish cross-dataset discovery.
- Time: certification history and recall dates; a revoked certificate is not currently valid.
- Hard negatives: similar model names, shared brand, certificate family vs affected variant, foreign vs
  domestic events, no recall found interpreted as safe. Sales suspension or safety advice is not authorized.

## Acceptance policy to implement after oracle freeze

Automatic acceptance applies to the requested evidence-backed comparison, not real-world causal effects
or consequential actions. Every required role/output must have observed lineage. Identity requires a
known issuer/namespace/granularity plus valid exact keys or an independently validated deterministic
mapping. Names and semantic similarity produce candidates only. Required time, space, units and coverage
must pass; contradictory source evidence prevents approval even when values match.

Separate computed checks from semantic decisions. A quote match establishes text presence; a calendar
intersection establishes overlap; neither establishes field meaning. Bind verification to the exact
observation and rule revision, including observedAt, validFrom/validTo and corrections/supersession.

If another observation can resolve a missing fact, continue acquisition/replanning within the goal budget.
Ask a person for an ambiguous goal choice, conflicting evidence that cannot be resolved, unsupported
probabilistic identity, or authorization for consequential action. Identify the particular unresolved
requirement and evidence needed. An always-review implementation fails every positive completion case.

## Evaluation gates

- Keep separate counts for retrieval, actual acquisition, executable candidates, approved correct outputs,
  false accepted links, unmet goals and human handoffs. Report denominators by case and match/action class.
- Every frozen positive must produce its expected values and pass its required evidence checks. All-review,
  all-abstain and silently reduced scope fail this gate even when no false positive is emitted.
- Known hard negatives must never be automatically accepted. Test missing evidence, source corrections,
  time/grain conflicts and namespace collisions. Zero errors on this set is not population precision 100%.
- Compare lexical-only and semantic-enabled discovery on the same frozen inputs and source snapshot;
  semantic.used proves use, not contribution. Do not give the unseeded planner oracle PKs or expected joins.
- Keep development and held-out records distinct. After a held-out failure informs a fix, that record becomes
  regression evidence; acquire a new held-out revision instead of continuing to call it unseen.
- Exercise CLI and MCP through their public interfaces. Report scripted and autonomous results separately.

## Storage decision

All five questions currently need scoped identity lookup, bounded composition, geographic comparison or
claim history. Retain current storage while establishing these contracts; a graph database is not a
prerequisite. Reopen storage only with a measured repeated path-query or concurrency need. This decision
does not remove the eventual requirement for durable, privacy-preserving evidence reuse and correction.
