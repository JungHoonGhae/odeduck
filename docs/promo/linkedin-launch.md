# LinkedIn 공개 글

## 게시글

높이 2m짜리 돌장승도 도둑맞는다는 사실, 알고 계셨나요?

공공데이터에서 발견한 기록입니다.
전남 진도의 돌장승 두 점. 하나는 2m, 다른 하나는 2.1m입니다.
도난 목록을 더 읽어보니 돌계단도 있었습니다.

휴대전화나 지갑을 떠올렸던 분실물 목록에서는 또 다른 장면이 나왔습니다.
울릉크루즈가 보관처로 등록된 ‘틀니’.
영화관이 보관처인 ‘녹색 케이스(틀니)’도 있었습니다.

통계표만 있을 줄 알았던 공공데이터에 이런 이야기가 숨어 있었습니다.

이 자료를 찾는 데 사용한 오픈소스가 ‘오데덕’입니다.
AI 에이전트가 공공데이터를 찾고, 접근 권한을 마련하고, 실제 내용을 가져와 살펴볼 수 있도록 만들었습니다.

사용자는 이런 요청으로 시작할 수 있습니다.

“공공데이터에서 사람들이 예상하지 못할 만큼 흥미로운 기록을 찾아주세요.”

어느 기관에 어떤 자료가 있는지, 검색어는 무엇인지, 어떤 명령어를 써야 하는지부터 공부할 필요가 없습니다. AI가 후보를 찾고, 실제로 열어볼 수 있는 자료인지 확인하며 탐색을 이어갑니다.

그런데 ‘데이터가 공개돼 있다’와 ‘지금 가져다 쓸 수 있다’ 사이에는 꽤 긴 거리가 있습니다.

이번 두 사례도 접근 방법이 달랐습니다.

돌장승 도난 기록은 공개 파일이었습니다. 오데덕이 찾아 확인한 공식 파일을 내려받아 읽으면 됐습니다. 로그인도 인증키도 필요 없었습니다.

틀니 기록은 경찰청의 데이터 조회 창구인 API를 이용했습니다. 이쪽은 활용신청과 인증키가 필요했습니다.

사람이 브라우저에서 로그인하자, 에이전트가 오데덕으로 신청 내역을 확인하고 필요한 API에 활용신청을 제출했습니다. 이후 오데덕이 계정의 인증키를 내부에서 처리해 실제 조회까지 이어갔습니다. 키를 채팅창에 복사해 넣을 필요는 없었습니다.

이번 API는 자동승인 대상이었습니다. 기관의 심사가 필요한 자료라면 그 승인은 기다려야 합니다.

핵심은 이 번거로운 중간 과정을 연결하는 데 있습니다.

AI는 다음에 무엇을 찾아볼지 판단합니다. 오데덕은 자료마다 다른 접근 조건을 확인하고, 신청과 인증을 처리하고, 실제 응답을 가져옵니다. 검색 결과에 나온 소개와 실제 데이터에서 확인한 내용도 구분합니다.

‘돌계단도 도난당하는구나’ 같은, 당장 어디에 써야 할지 모르겠는 지식을 찾는 데서 시작했지만, 같은 접근은 훨씬 실용적인 질문으로 이어질 수 있습니다.

우리 동네에 가게를 열기 전에 살펴볼 자료는 무엇일까요?
지금 내 사업에 맞는 지원사업은 무엇일까요?
식재료 가격은 어느 시장에서 어떻게 움직이고 있을까요?

물론 이런 질문에 답하려면 기간과 단위를 맞추고, 빠진 자료도 확인해야 합니다. 오데덕이 계속 풀어가려는 문제입니다.

저는 공공데이터가 아직 충분히 채굴되지 않은 다이아몬드 광산 같다고 생각합니다.
좋은 정보가 없어서라기보다, 들어가는 길과 꺼내 쓰는 과정이 너무 복잡했던 것은 아닐까요.

오데덕을 오픈소스로 공개했습니다.
여러분이라면 이 안에서 무엇을 찾아보고 싶으신가요?

### 재현 경로

- 자료 발견은 오데덕 카탈로그 검색, 계약·파일 확인은 `inspect_dataset`으로 수행했습니다.
- 넓은 요청에서 에이전트가 검색 개념을 골랐습니다. 유실물·도난 유산은 사용자가 든 예시이기도 하므로 무힌트 자율 발견 평가로 해석하지 않습니다.
- CSV는 오데덕 검사가 반환한 공식 다운로드 URL에서 호스트가 내려받아 읽었습니다. 검사에 기록된 SHA-256과 파일의 해시가 일치했습니다: `72ed0e491d89e1b51d2eeb092c26343bbb372a000b8b31cd462071080b6c20b2`.
- 처음 연결된 MCP는 로컬 CLI와 로그인 세션을 공유하지 않았습니다. 사람이 로컬 `login`을 완료한 뒤 같은 로컬 CLI로 신청·호출을 이어갔습니다. 당시 main `429ab60`에서 빌드한 실행 파일을 사용했습니다.
- 최초 API 호출에 `--wait 10m`을 주어 승인 전파 대기를 허용했습니다. 이는 실제로 10분 기다렸다는 뜻이 아닙니다.
- `PRDT_NM=틀니` 검색 응답의 `totalCount=245`는 검색 일치 기록 수입니다. 틀니함·복합 물품명도 포함하므로 틀니 245개로 표현하지 않습니다.
- `DEP_PLACE=지하철`을 함께 지정한 조회는 0건이었습니다. 이 검색만으로 지하철 틀니 분실의 존재·부재를 결론 내리지 않았고 게시글에는 사용하지 않았습니다.
- 앞서 별도로 조회했던 외부 검색 서비스 결과는 이 글의 사실 근거로 사용하지 않았습니다.
- 공개되지 않은 계정 신청 목록, 쿠키·인증키, 소유자 정보는 기록에 포함하지 않았습니다.

```sh
odeduck inspect 15089237 --observe -f json
odeduck inspect 15057670 -f json
odeduck applications -f json
# 세션이 없거나 만료됐을 때만 사람이 브라우저에서 로그인합니다.
odeduck login
# 아직 신청하지 않았고 사용자가 해당 신청을 허용했을 때 실행합니다.
odeduck apply 15057670 --purpose '공개 습득물의 의외의 물품 사례 확인' --category ref
odeduck call --pk 15057670 --op getPtLosfundInfoAccTpNmCstdyPlace \
  --param PRDT_NM=틀니 --param pageNo=1 --param numOfRows=10 --wait 10m -f json
```

게시글은 작성본입니다. LinkedIn에는 게시하지 않았습니다.
