# Agent Skill로 오데덕 사용하기

[README](../README.md#빠른-시작) · [사용자용 Skill 원본](../skills/odeduck/SKILL.md)

`odeduck` Skill은 에이전트가 목표에 필요한 자료를 발견하고 보고·비교·계산과 근거까지 이어가는
사용 절차다. 산출물을 요구하면 `solve`·`advance_goal`로, 자료 찾기나 단일 조회를 요구하면
검색·검사·신청·호출로 안내한다. 설치와 MCP 연결이 빠져 있으면 해당 설정부터 안내한다. Skill 자체에는 실행 엔진이나
인증정보가 들어 있지 않으며, CLI 또는 MCP가 실제 작업을 수행한다.

## 설치

Node.js와 `npx`가 있는 환경에서 실행한다. 사용할 에이전트와 설치 범위는 설치 화면에서 고른다.

```sh
npx skills@latest add JungHoonGhae/odeduck --skill odeduck
```

`--skill odeduck`은 사용자용 Skill만 고른다. 저장소의 개발·사업 검토용 Skill을 함께 설치할 필요는 없다.
MCP만 연결해도 오데덕을 사용할 수 있고, Skill은 선택 사항이다.

아직 원격에 반영하지 않은 로컬 변경을 사용하려면 이 저장소 루트에서 설치한다.

```sh
npx skills add ./skills/odeduck
```

설치 문법과 지원 에이전트는 [Skills CLI 공식 안내](https://github.com/vercel-labs/skills#install-a-skill)를 따른다.

## 첫 요청

설치한 에이전트에서 새 대화를 열고 다음처럼 요청한다.

> odeduck 스킬로 최근 공영도매시장 양파 가격을 시장별로 비교해줘. 등급·단위·기간을 맞추고, 비교할 수 없는 자료와 출처도 표시해줘. 필요한 API는 신청하고 승인 상태를 확인해줘.

검색·검사는 로그인 없이 시작할 수 있다. 활용신청·인증 조회에 로그인 세션이 필요하면
`odeduck login`으로 정부 SSO를 직접 마친다. 신청은 계정에 실제 기록을 남기므로 에이전트의 승인
정책이 적용되며, 기관 심의는 기다려야 한다. 파일·외부 제공기관 자료는 검사된 제공형에 맞게 처리한다.
목표 실행의 의미 검색·결과 검토에는 별도 준비가 필요하다. `solve` 자체의 자동 신청은 현재 지원하지
않으므로 필요한 접근권한은 일반 신청 경로로 마련한다. [목표 실행 설정](advanced-usage.md#목표에서-결과까지-실행하기--experimental)을 참고한다.

## 실행 구조

| 구성 | 책임 | 배포 위치 |
| --- | --- | --- |
| Agent Skill | 목표 실행 또는 개별 조회로 진입하고, 필요한 접근·결과 해석을 안내 | `skills/odeduck/` |
| MCP / CLI | 에이전트 또는 터미널의 요청을 같은 엔진으로 전달 | `odeduck mcp` / `odeduck` |
| Goal engine | 필요한 역할·원천을 탐색하고 취득·계산·재탐색·산출물 평가를 진행 | `advance_goal` / `odeduck solve` |
| Go 실행 엔진 | 실제 계약 검사, 자격증명 취급, 신청·호출과 검증 | 플랫폼별 릴리스 바이너리 |
| 개발용 Skills | 이 저장소의 사업 검증·그래프 설계 작업을 안내 | `.agents/skills/` |

사용자용 Skill은 폴더만 설치해도 동작하도록 설정과 개별 API 접근 안내를 내부 `references/`에 포함한다.
개발용 Skill이나 저장소 전체 체크아웃은 실행 의존성이 아니다. 상세 MCP 스키마와 최신 오류 안내는
연결된 런타임에서 읽으며, Skill이 실행 계약이나 권한을 덮어쓰지 않는다.

## 개발용 Skills를 확장할 때

개발용 Skill은 역할별로 짧은 진입 문서와 작업별 `references/`를 둡니다. 사용자용 Skill과 같은
단계적 읽기 구조를 쓰되, 사용 안내와 개발 판단의 책임은 분리합니다.

| 진입점 | 필요한 작업에서만 읽는 상세 문서 |
| --- | --- |
| [데이터·목표 실행 개발](../.agents/skills/odeduck-graph-engineering/SKILL.md) | 탐색과 런타임 · 데이터 계약 · 평가 · 아키텍처 |
| [사업 검증](../.agents/skills/odeduck-business-harness/SKILL.md) | 사업 가설과 데이터 근거 · 상업 검증 |

확장 위치는 **누가 언제 읽어야 하는가**로 정합니다.

| 바뀌는 내용 | 반영 위치 |
| --- | --- |
| 모든 기여자에게 필요한 저장소 작업 원칙 | `CLAUDE.md`의 해당 절 |
| 기존 작업의 전문 판단 기준 | 해당 Skill의 reference |
| 기존 Skill 안의 별도 작업 절차 | 새 reference와 진입 표의 행 |
| 독립적인 호출 시점·도구·절차를 가진 작업 | 새 Skill |
| 제품 계획기의 실제 탐색·재계획 행동 | `internal/goalwork/planning-guide.md`와 전달 경로 |
| 명령·도구 인자·지원 기능·권한·완료 상태 | CLI/MCP 실행 코드와 런타임 가이드 |
| 특정 원천의 정답·실패·평가 수치 | 해당 계약·fixture·평가 기록 |

새 기능마다 새 스킬이나 공통 framework를 만들 필요는 없습니다. 반복되는 규칙은 소유 문서 하나에서
관리하고 필요한 곳에서 연결합니다. 짧은 설명에는 적용 작업을 쓰고, 본문에서 요청과 무관한 조사나
검증을 일괄 실행하게 하지 않습니다. 스킬 이름을 바꾸면 `CLAUDE.md`와 기존 참조도 함께 갱신합니다.

확인은 변경 범위에 맞춥니다. 설명과 분기표가 실제 요청을 맞는 안내로 보내는지, 링크가 유효한지,
설치되는 Skill의 reference가 함께 전달되는지를 확인합니다. 제품 행동을 바꿨다면 스킬 검증과 별도로
해당 CLI/MCP 계약을 테스트합니다. 외부 배포 스킬은 원문을 유지하고, 이 저장소 소유 지침만 수정합니다.

설계 근거는 [OpenAI 공식 가이드 검토](agents/harness-sources.md#개발용-skill-구조--2026-09-16)에 있습니다.

## 버전이 바뀔 때

설정 안내는 최신 정식 릴리스 설치 주소를 사용한다. Skill에 바이너리 버전별 계약을 복제하지 않고
실행 중인 CLI의 `version`·`--help`, MCP의 도구 스키마·`odeduck://guide`에서 지원 범위를 확인한다.
바이너리 업데이트 후에는 MCP 서버도 다시 연결한다. Skill은 사용하는 설치 도구로 별도 갱신한다.
재현을 위해 사용자가 고정한 버전은 유지하며, 필요한 기능이 없으면 차이를 알리고 업데이트를 안내한다.

**현재 배포 경로는 자동 업데이트가 아니다.** `latest`는 설치 명령을 실행하는 시점의 최신 버전을
뜻한다. 실행 중인 바이너리나 이미 읽은 Skill 문서가 백그라운드에서 교체되는 것은 아니다.

| 바뀐 대상 | 갱신 방법 | 반영 시점 |
| --- | --- | --- |
| GitHub에서 설치한 Skill | 설치 범위를 골라 `update odeduck` 실행 | 새 에이전트 대화에서 다시 로드 |
| 로컬 경로에서 설치한 Skill | 원본 변경 후 같은 로컬 경로로 재설치 | 새 에이전트 대화에서 다시 로드 |
| Go 바이너리·동봉 카탈로그 | README의 최신 정식 릴리스 설치 명령을 다시 실행 | CLI는 다음 실행, MCP는 서버 재연결 후 |
| MCP 도구 스키마·가이드 | 업데이트한 바이너리로 MCP 서버 재연결 | 새 연결의 도구·가이드 확인 시 |

```sh
npx skills@latest update odeduck --project
```

프로젝트 설치는 해당 프로젝트에서 실행하고, 전역 설치는 `--project`를 `--global`로 바꿉니다.
로컬에서 직접 수정한 Skill은 변경 내용을 먼저 보존한다.

호스트가 관리하는 플러그인 자동 업데이트는 별도의 배포 방식이다. 현재 설치 명령은 이를 설정하지 않는다.
사용자용 Skill은 짧은 진입·판단 원칙을 유지하고, 버전별 동작은 런타임이 제공하도록 구성했다.
[gstack·Matt Pocock 구조 검토와 채택 범위](agents/harness-sources.md#사용자용-skill-배포-구조--2026-09-16)를 참고할 수 있다.

## 로컬 설치 확인

설치 없이 발견되는 Skill을 확인할 수 있다.

```sh
npx skills add ./skills/odeduck --list
```

실제 설치 검증은 별도 임시 프로젝트에서 위 폴더의 절대 경로를 사용한다. 프로젝트 범위로 설치하고
`SKILL.md`와 모든 `references/` 파일이 함께 전달되는지 확인한다. 전역 설치는 이 검증에 필요 없다.
