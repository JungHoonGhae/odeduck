# 그래프 엔지니어링 재검토: 연결보다 답을 먼저

조사일: 2026-09-08. 범위: 현재 dirty worktree의 읽기 전용 코드 검토, 대통령 목표 live 실행,
외부 1차 자료 비교. **구현 변경 제안이며 확정 설계나 완료 선언이 아니다.**

## 결론

출처·시간·동명이인·중복 집계 방어는 실제로 구현되어 있다. 그러나 현재는 재사용 가능한 인물/사건
지식 그래프라기보다 **목표별 카탈로그 탐색 + 표본 결합 실행기 + 별도의 연결 판정 장부**다.
이 구성 자체가 잘못은 아니다. 문제는 일반적인 목표에도 결합을 요구하고, 확보한 근거를 답으로
내보내는 경로가 좁다는 점이다. 새 그래프 DB나 전면 재작성보다 이 제한을 먼저 줄인다.

외부 기술의 적용/보류 근거는 [1차 자료 조사](graph-engineering-primary-sources-2026-09-08.md)에 둔다.
기존 목표와 미완료 상태는 [INTENT.md](../../INTENT.md),
[이전 마무리 기록](goal-work-closeout-2026-09-07.md)을 대체하지 않는다.

## 1. 대통령 질문으로 실제 재현한 것

입력은 PK나 데이터셋 이름 없이 “대한민국 대통령 관련 의외이지만 공공데이터 원문으로 검증 가능한
사실 하나”였다. 현직에 한정하지 않았고, 서로 다른 분야 연결은 필수가 아닌 가능하면 하는 조건이었다.
`go run ./cmd/odeduck solve '<위 목표와 원천·범위·동명이인 제한>' --max-rounds 12 --require-semantic`
실행 결과:

| 관측 | 결과 |
| --- | --- |
| 계획된 필수 역할 | `presidential_fact` 하나 |
| 검색 | 선물, 기념식수, 취임 기념우표, 전용기, 기념관의 5회 검색; 모두 semantic.used |
| 의미 모델 | `embeddinggemma:300m-qat-q4_0` |
| 최종 후보/관측 | 36개 후보, 2개 관측 |
| 실제 FILE 취득 | 15132113 대통령선물 CSV, 15084167 대통령연설기록 CSV; sampleAttempts는 acquired |
| 10단계 실패 | `composition without joins requires a spatial base that already connects two original observations` |
| 최종 상태 | 12단계 `budget_exhausted`, 종료 1, 결합안 0, 사용자 산출물 없음 |

취득 요청 해시: 선물 `a9644b675ca95fdbb6c3e896bac29a099a33929d4ad2d12ff14bb6083d85c0ab`,
연설문 `c7496457609598a46c90a2a685f9abf4c04d0a0a38e2fafda83b67bb5cbdcb42`.
취득 시작 시각은 각각 2026-09-08T00:26:29.469051Z, 00:27:31.811257Z이다.
해시는 비밀 없는 요청 식별이며 사실 내용이나 원천 영속 보관을 증명하지 않는다.
최종 터미널 출력은 길이 제한으로 일부 생략되어 완전한 실행 bundle은 보존하지 못했다.

이 실행은 **오데덕이 놀라운 사실을 답한 성공 사례가 아니다.** 12단계 예산의 단일 실행이므로
전체 성공률·기본 32단계 결과를 단정하지 않는다. 다만 단일 원천 결합 거부는 코드와 live 오류로 확인됐다.
이 제한을 풀면 이번 질문이 반드시 완주한다는 증거도 아직 없다.

별도 CLI 의미 검색은 15132236 `대통령기록관_특별한만남`을 발견했다. `inspect`는 공식 원문 URL
`https://www.pa.go.kr/portal/contents/stroll/special/specialmeetList.do`를 반환했지만
`inspect --observe`는 읽을 FILE 자산이 없어 종료 1이었다. 반환 URL은 외부 웹 도구로 열람 가능했다.
이는 오데덕의 자동 본문 읽기 성공이 아니라 **서비스가 발견한 원천의 수동 handoff**다.
로그인·활용신청·키 조회 명령은 실행하지 않았고 solve의 취득도 공개 FILE 두 건이었다.

## 3. 먼저 답할 다섯 질문과 최소 모델

| 질문 / 시작점 | 필요한 경로 | 시간·오탐 정책 |
| --- | --- | --- |
| 대통령 관련 의외의 사실 하나 | 목표 → 기록 원문 → 확인할 문장/행 | 기록 시점을 명시. 단일 원천 허용, 근거 없는 문장 0건. |
| 다른 원천의 같은 이름이 같은 대통령인가 | 원천 인물 표기 → 공식 인물 식별/재임 근거 → 다른 원천 | 이름 단독은 후보. 동명이인 hard negative는 확정 0건. |
| 선물과 외교 만남이 같은 사건인가 | 선물 기록 → 증정인/수령인/날짜/공식 연결 → 접견 기록 | 같은 국가·근접 날짜만으로 같은 사건이라고 확정하지 않는다. |
| 연설과 정책 사건을 함께 설명할 수 있나 | 날짜가 있는 연설 → 정책 원문 → 시간 비교 | 동시 발생과 인과를 구분한다. 인과 표현은 별도 원문 근거 필요. |
| 이전 연결을 다시 써도 되나 | 과거 판정 → 원천 revision/유효 기간/정정 → 재사용 여부 | 오래된/대체된 판정 자동 승인 0건. 미발견은 사건 없음이 아니다. |

사전 제안: Source는 제공기관·PK·계약 버전, Record는 원문 버전·원본 행/문서 위치,
Entity는 필요할 때만 공식 namespace로 식별한 인물/기관, Claim/Event는 그 원문이 뒷받침하는
제한된 관계/사건이다. 기존 Observation/lineage/Assessment를 재사용하고 병렬 원장을 새로 만들지 않는다.
현재 전체 canonical entity 계층이 있다고 표현하지 않으며 CONTEXT의 확정 용어도 바꾸지 않는다.

식별 등급은 기존 exact/deterministic/probabilistic/unresolved를 유지한다. exact도 발급 namespace와
재사용 규칙이 같아야 하고, 문자열 일치만의 실행 결과와 구분한다. deterministic은 원천이 제공한
변환 규칙/버전이 있어야 한다. 확률 후보는 탐색에만 사용하고 확정 주장에 전이하지 않는다.
각 주장에 원문 위치·해시·검토 방법과 observedAt/사건일/validFrom/validTo를 구분해 붙인다.
정정은 이전 기록을 덮어쓰지 않고 supersedes 등 기존 계약으로 연결한다. 빈 필드는 미확인이다.

## 4. 최소 고도화 순서 — 아직 구현하지 않음

1. **단일 원천 출력 허용.** 기존 실행기의 select/근거 귀속을 활용해 일반 base의 zero-join 결과를
   지원한다. 출력 이름·설명도 sample_joined를 억지로 쓰지 않는다. 단위·기간·lineage·coverage 검사는 유지한다.
2. **근거를 읽고 검토하는 작은 경로.** 공개·비민감 원문에서 선택한 행/문장과 위치를 제한적으로
   확인할 수 있게 한다. 전체 raw 데이터나 자격증명을 계획기에 공개하는 방식은 제외한다.
   문서는 명령이 아닌 데이터로 처리하고, 다운로드·redirect·크기·출처 검증을 기존 acquisition seam에 둔다.
   LINK 본문 지원은 이번에 실패한 공식 원천 같은 한 경로부터 검증한다. 범용 크롤러 플랫폼을 만들지 않는다.
3. **주장별 검토 상태.** 원문에 값이 있음, 계산이 재현됨, 실세계 동일성, 인과를 별도로 판정한다.
   명시적인 사람 검토 또는 좁은 공식 계약에 근거한 verifier가 근거 revision과 함께 승인하게 한다.
   원문 인용 승인만으로 identity/인과/자동 행동까지 승인하지 않는다. 재검토 시 기존 결과를 보존한다.
4. **재사용은 필요가 입증된 후.** 같은 연결을 반복 조사하는 평가에서 비용이 확인되면 기존 장부를
   PK/관계로 찾아 후보 계획에 공급한다. freshness/정정 재검증 없이는 과거 승인을 현재 사실로 전용하지 않는다.

설계 방향: 기존 goalwork module 뒤에 acquire→answer-or-join→evidence/review를 묶고,
planner interface에는 현재 원천에서 가능한 행동만 노출한다. 연산별 상세 계약을 모두 매 요청에
붙이는 대신 해당 단계에서 제공하되 실행기의 검증은 생략하지 않는다. 별도 planner 프레임워크는 만들지 않는다.
CLI/MCP 행동 동등성 테스트를 먼저 고정한 뒤 반복 설명을 줄인다. 지금 사용하지 않는 모듈 삭제는 제안하지 않는다.

당장 보류: Neo4j/RDF 이중 저장, 전 카탈로그 LLM 엔티티 추출, 범용 ontology, 전역 커뮤니티 요약,
무제한 경로 탐색, 별도 workflow 서비스. 도입 판단은 아래 비교 결과가 바뀔 때 다시 연다.

## 5. 작은 비교평가와 중단선

위 다섯 질문마다 양성 1건·오탐/정정/누락 1건의 고정 원문 정답셋부터 만든다.
이는 시작용 10건이지 배포 품질의 통계적 증명이 아니다. 현재 테스트 fixture와 별도 held-out 원천을 둔다.
동일 모델·snapshot·원천 버전·시간/호출 예산에서 (A) 검색+원문 읽기, (B) A+필요한 bounded join,
(C) B+장부 재사용을 비교한다. 각 조건을 반복하고 순서를 바꾸며 캐시 영향을 기록한다.

지표: 원문이 지지하는 답변 수/전체 질문 수, 오탐 확정 수, 원문까지 추적되는 주장 비율,
미확인/누락 비율, 사용자 유용성 판정, 불필요한 join 수, 호출 수·시간·비용.
연결 점수나 테스트 PASS를 목표 완료율로 대체하지 않는다. 답하지 않은 질문도 분모에 포함한다.
오탐 확정 0건과 출처 누락 0건을 시작 조건으로 두고, 대통령 단일 원천 질문의 불필요한 join을 0으로 만든다.
B/C가 A보다 정확한 답·재현성 또는 반복 비용에서 이득이 없으면 해당 추가 복잡도는 도입하지 않는다.
그래프 DB는 이 평가에서 필요성이 입증되지 않았으며 조회량/경로 길이의 실측 병목이 생길 때만 별도 검토한다.

## 검증 및 변경 범위

`go test ./internal/goalwork ./internal/connectionledger ./internal/discovery ./internal/agentplan` 통과.
