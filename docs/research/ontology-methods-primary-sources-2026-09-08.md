# 온톨로지 방법론: 오데덕 적용을 위한 1차 자료 검토

검토일: 2026-09-08. 상태: 연구 제안이며 구현·성능 검증·표준 준수 선언이 아니다.
범위: 의미 사전, 원천 매핑, 제약 검사, 관측 모델, 카탈로그 모델, 가상 지식 그래프.
제품 의도는 [INTENT.md](../../INTENT.md)가 우선하며, 아래 질문은 평가 사례 제안이지 실제 데이터 확보 주장이나 새 제품 범위가 아니다.

## 1. 결론: 의미 계약을 자산으로 만들고 실행 기술은 교체 가능하게 둔다

온톨로지를 배제할 이유는 없다. 필요한 최소 단위는 **질문에 쓰이는 개념·관계의 뜻과 원천 필드 매핑을 명시하고 버전 관리하는 계층**이다.
이는 임베딩 유사도와 별개로, 같은 단어의 다른 의미와 다른 단어의 같은 의미를 다룬다. 다만 개념 대응은 실제 행의 동일 대상 판정과 분리해야 한다.
권고는 아래 표준의 의미를 선택적으로 재사용하는 것이다. JSON/Go 구현에 표준 이름만 붙여 RDF·SKOS·SHACL 준수를 주장하지 않는다.

## 2. 질문으로 경계를 정한다

[Ontology Development 101 §3](https://protege.stanford.edu/publications/ontology_development/ontology101-noy-mcguinness.html)은 용도·유지관리자·답할 질문을 먼저 정하고, 기존 모델 재사용과 반복 개정을 권한다.
공식 HTML은 웹 도구 파싱 실패 뒤 같은 Stanford URL을 HTTP로 읽어 해당 본문을 확인했다. 오래된 편집기 사용법과 현재 도구 호환성은 채택하지 않는다.

| 평가 질문 제안 | 시작점 → 필요한 경로 | 시간 / 허용 오탐 | 최소 실행 |
| --- | --- | --- | --- |
| 단일 공식 기록에서 확인할 수 있는 사실은 무엇인가? | 질문 → 원천 기록 → 해당 행·문장 | 기록 당시 / 출처 없는 사실 0 | 단일 원천 읽기, 결합 불필요 |
| 이름이 다른 두 기록은 같은 기관을 말하는가? | 기록 A → 식별자·기관 변경 근거 → 기록 B | 기관 변경 전후 / 확정 동일시 오탐 0 | 명시적 대응표와 bounded join |
| 한 문서의 주제가 다른 분야 문서에도 나타나는가? | 원문 문장 → 주제 개념 → 다른 원천 문서 | 각 문서의 사건일·공개일 / 관련 후보 허용, 인과 단정 0 | 개념 기반 검색 + 인용 |
| 같은 지역의 폭염과 취약 인구를 비교할 수 있는가? | 기상 관측 → 지역 대응 → 인구 통계 | 관측 시점·집계 기간·경계 버전 / 잘못된 지역 합산 0 | 검증된 공간·시간 매핑 |
| 정정된 계약을 반영하면 과거 답변이 달라지는가? | 답변 → 사용 claim → 원천 revision → 정정 claim | 당시 관측·효력 시점 / 구버전을 현재로 제시 0 | 의존성 조회와 재평가 |

위 0은 높은 비용의 오탐을 금지하는 제품 정책이다. 작은 표본에서 오류 0건을 관찰해 모집단 오류율 0을 보장할 수는 없다.
대통령 선물·연설 질문은 이 중 단일 원천/주제 연결 유형의 회귀 사례일 뿐이다. `President` 같은 특정 질문의 클래스·필수 관계·정답 경로를 공통 코어에 넣지 않는다.

## 3. 방법별 얻는 것과 경계

| 방법 / 읽은 1차 자료 | 해결하는 문제와 오해하기 쉬운 경계 | 오데덕 최소 적용 제안 / 비용 |
| --- | --- | --- |
| [SKOS §8·10](https://www.w3.org/TR/skos-reference/#mapping) | 개념의 표제·동의 표기·상하위·개념 체계 간 대응. `closeMatch`와 `related`는 비전이, `exactMatch`는 전이다. 이는 검색용 개념 대응이지 두 회사·사람의 동일성 등급이 아니다. | 검토한 개념 ID·정의·대체 표기·관계별 허용 확장만 JSON으로 보존. 운영 서버보다 원천별 의미 검토 비용이 핵심. 전이를 끈 자체 규칙을 SKOS 준수라고 부르지 않음. |
| [OWL 2 Primer §1.3·4.7](https://www.w3.org/TR/owl2-primer/) / [Direct Semantics §2.3.5–6](https://www.w3.org/TR/owl2-direct-semantics/#Keys) | 열린 세계에서는 미기록이 거짓이 아니며 다른 이름도 다른 개체를 보장하지 않는다. `HasKey`는 조건 충족 개체의 동일성을 함의한다. DB unique 제약처럼 중복 행을 거부하는 기능이 아니다. | 클래스·관계 정의는 활용하되 `sameAs`·키 추론은 검증된 식별 계약 뒤에 둠. 자동 분류·논리적 함의가 실제 질문에 필요해지면 제한된 프로파일 추론기 평가. 모델 검토·추론 설명·충돌 처리 비용 추가. |
| [SHACL §3·4.8.1](https://www.w3.org/TR/shacl/#validation) | 데이터 그래프를 shapes와 대조하고 위반을 보고한다. `sh:closed`는 허용 속성을 제한한다. 유효성 통과가 원천 사실·실제 동일성·완전한 coverage의 참을 입증하지는 않는다. | 현재 Go 검사에 필드 경로·규칙 revision·실패 이유가 남는 계약 테스트. RDF 교환 요구가 생기면 실제 SHACL 프로세서와 적합성 테스트 도입. 두 검증 사전을 따로 손으로 유지하지 않음. |
| [SOSA/SSN §4.3·4.7](https://www.w3.org/TR/vocab-ssn/#SOSAphenomenonTime) | 관측 행위, 관측 대상, 속성, 결과를 분리한다. `phenomenonTime`은 결과가 적용되는 때, `resultTime`은 관측 완료 시각이다. 후자는 오데덕이 파일을 가져온 시각이 아니다. | 기상·환경 등 측정 자료의 관측 패턴에 적용. 원천 관측 시각과 수집 `observedAt`을 별도로 보존. 선물 수령·계약·정책 주장을 모두 센서 관측으로 모델링하지 않음. |
| [DCAT 3 §6.6·6.8·6.9](https://www.w3.org/TR/vocab-dcat-3/#Class:Distribution) | 개념적 Dataset, 제공 표현 Distribution, 호출 기능 DataService를 분리한다. 동일 dataset의 distribution도 정밀도·공간/시간 해상도 등이 다를 수 있다. API+FILE이라는 이유로 동일 행·coverage를 가정할 수 없다. | 현 composite 카탈로그와 inspection의 세 경계를 매핑. 표현별 관측·coverage를 유지. 외부 카탈로그 교환이 필요할 때 DCAT RDF export를 별도 검증; 지금 전 원천을 RDF 변환할 필요는 미입증. |
| [OWL 2 QL §3](https://www.w3.org/TR/owl2-profiles/#OWL_2_QL) / [Ontop 개념](https://ontop-vkg.org/guide/concepts.html)·[mapping](https://ontop-vkg.org/guide/advanced/mapping-language.html) | OBDA/VKG는 온톨로지 질의를 원천 SQL로 재작성하여 복사 없이 관계형 데이터를 조회한다. 원천 테이블과 명시적 매핑이 필요하다. 임의 포털 REST·CSV를 자동 의미 연결하거나 SSO·신청을 대신 해결하지 않는다. | 안정적 SQL 관측 저장소·반복 교차질의가 성장하면 실행 계층 교체 후보. 지금은 ontology/SQL mapping 운영 비용과 수집·정정 pipeline까지 포함해 비교해야 함. |

OWL은 데이터베이스와 상극이 아니다. OWL 2 QL은 관계형 저장소를 활용하도록 설계된 프로파일이다. 따라서 장기 대안은 “현재 Go만 유지”와 “전부 그래프 DB로 교체”의 양자택일이 아니다.
단, [QL §3.1](https://www.w3.org/TR/owl2-profiles/#Feature_Overview_2)은 `HasKey`·`SameIndividual`·전이 속성·property chain을 지원 범위에서 제외한다. QL 기반 가상 그래프를 선택해도 동일 대상 해소나 임의 다단계 추론이 저절로 생기지는 않는다.

## 4. 현재 코드와 정확히 연결되는 지점

- [source_declaration.go](../../internal/goalwork/source_declaration.go)는 공급자 선언을 `publisher_declared`로 구분하고 관측된 행의 namespace·기간·공간 검증으로 승격하지 않는다. DCAT 해석에서도 유지할 경계다.
- [scope_vocabulary.go](../../internal/goalwork/scope_vocabulary.go)는 동결한 시도 표기 대응의 revision·해시·출처를 보존한다. 수치 코드 crosswalk도 시설 동일성 증명도 아니라는 주석이 명확하다. 이미 작은 의미 매핑 자산의 출발점이 있다.
- [scope.go](../../internal/goalwork/scope.go)는 토큰 검사와 `MeaningVerified`를 구분한다. 이 필드를 온톨로지 추가만으로 참으로 바꾸는 것이 아니라, 해당 필드 의미·매핑·효력 기간에 대한 검증 근거가 필요하다.
- 현재 읽은 세 파일만으로 시스템 전체에 범용 온톨로지, RDF/SHACL 실행기, 장부 재활용이 구현됐다고 판정하지 않았다.

## 5. 제안하는 작은 의미 계약

아래는 확정 도메인 사전이나 신규 API가 아니라 다음 설계 실험의 항목이다. 저장은 기존 JSON/표로도 가능하다.

| 대상 | 최소 내용 | 소비 경계 |
| --- | --- | --- |
| 개념 | 안정 ID, 정의·제외 범위, 표제/대체 표기, 관련 질문 | 검색 확장에 사용; 식별 확정에 직접 사용하지 않음 |
| 원천 필드 매핑 | dataset·delivery·revision·field path → 개념, 단위·grain·기간·코드 namespace | 원천별 계약이며 질문별 정답 recipe가 아님. 자동 추정은 `proposed`; 검토·실제 행 검증 후 제한된 실행에 사용 |
| 식별 계약 | 발급기관·namespace·키 필드·정규화 버전·재사용/변경 규칙 | `exact / deterministic / probabilistic / unresolved` 등급별 허용 행동 |
| 관계/claim | 주어·동사·목적어 또는 n항 사건, source record, 방법, 효력 기간, 관측일, 대체 관계 | 인과·동일성·주제 연관을 서로 다른 관계로 유지 |
| 검증 결과 | 입력 snapshot, 계약 revision, 실행 규칙, 통과/위반/미확인, 적용 범위 | 구조 적합성과 현실 의미의 검증을 별도로 보고 |

Source는 제공 계약, Record는 원문 행·문서, Entity는 실제 대상, Claim/Event는 출처와 시점이 있는 주장·사건으로 유지한다. 개념 사전은 다섯 번째 거대한 세계 지식 저장소가 아니라 이 층들을 해석하는 관리 메타데이터다.
원천 부재·coverage 미상·파서 실패는 구별하며, 이름 유사도는 후보만 만든다. 정정 시 이전 claim을 덮어쓰지 않고 대체 관계를 보존한다.

## 6. 오래 유지하기 위한 운영 규칙 제안

1. 매핑마다 담당 검토자, 근거 URL/선택 위치/해시, 질문 또는 평가 fixture, revision을 지정한다. 담당자가 없는 자동 생성 매핑은 실행 승격하지 않는다.
2. 상태는 제안→검토 완료→비활성/대체로 관리한다. 의미가 바뀌면 새 revision 또는 새 개념 ID를 발급하고, 단순 표기 수정과 구별한다.
3. 추출 schema·코드 체계·행정구역·효력 기간의 변경이 감지되면 의존 매핑과 답변만 재검증한다. 과거 실행은 당시 revision으로 재현한다.
4. LLM은 후보와 근거 초안을 만들 수 있지만, 동일성·매핑 승인과 골드 정답을 단독 생성하지 않는다. 검토 반려도 hard negative로 축적한다.
5. 평가에는 동일명 타기관, 코드 namespace 충돌, 분할·통합 지역, API/FILE coverage 차이, 정정 사건, 식별 불가를 포함한다. 자동 확정 정확도와 유용한 답변 coverage를 함께 보고, 무조건 abstention으로 안전성 점수를 올리지 않는다.
6. 쓰이지 않는 개념은 즉시 삭제보다 비활성화·의존성 확인을 우선한다. 원천 검증 비용과 절감된 반복 작업을 기록해 다음 확장 대상을 결정한다.

과적합 검사는 질문을 섞는 것만으로 부족하다. 도메인·제공기관 단위 held-out을 분리하고, 보지 않은 원천을 처리하는 무사전 매핑 조건과 사람이 매핑한 적응 조건의 결과·검토 시간을 따로 보고한다. 테스트 원천·정답으로 사전을 수정했다면 그 결과를 zero-shot 일반화로 보고하지 않는다. 동일 원천의 질문 표현만 바꾼 성공은 별도 회귀 지표다.

## 7. 아키텍처 교체를 정당화하는 증거

- **OWL/SHACL runtime**: 실제 외부 표준 모델 교환 또는 반복 분류·함의 질의가 있고, 기존 검사보다 오류 발견·변경 일관성을 개선하는 재현 실험. 형식 직렬화만 필요하면 export로 충분할 수 있다.
- **OBDA/Ontop**: 안정적 관계형 관측 저장소 위에서 여러 소비자가 같은 의미 질의를 재사용하며, 기존 결합의 유지 비용·정정 추적·질의 성능이 실제 병목일 때. 매핑 작성·SQL 실행·인증 경계를 포함한 대조 실험이 먼저다.
- **물리 그래프 저장소**: 질문의 핵심이 가변 길이 관계 경로이고, 표 기반 실행과 같은 입력·정답으로 비교한 지연·비용·재현성 결과가 교체를 지지할 때.

현재 구조를 보존하는 것 자체는 목표가 아니다. 먼저 의미 계약과 실제 질문 평가를 저장 기술에서 분리하면, 검증 근거를 유지한 채 실행 계층 또는 전체 구조를 교체할 수 있다.
본 조사에서는 제품 코드·인증·원천 호출을 변경하지 않았으며, 도입 효과·처리량·운영비 수치는 아직 측정하지 않았다.
