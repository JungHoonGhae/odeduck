## 결론

가장 먼저 검증할 사업은 **다사업장 폭염 안전 컴플라이언스 OS**다. 건설 원청, 물류·시설관리·제조
본사가 여러 현장의 기상 위험을 한 화면에서 보고, 현장 측정값에 따라 휴식·작업조정 조치를 내리고,
관리자와 작업자의 확인을 받아 증빙으로 남기는 B2B SaaS다.

핵심은 날씨 알림이 아니다. 기상청은 이미 폭염 영향예보를 카카오톡으로 무료 전달하고 있으며,
고용노동부도 점검표와 기술지원을 제공한다. 유료 가치는 `위험 탐지 → 현장 측정 → 조치 지시 → 사람의
승인·확인 → 누락 에스컬레이션 → 감사 가능한 기록`이라는 운영 폐쇄루프에 있다. odeduck은 그 뒤에서
기상·특보·재해 데이터의 검색, 계약 검사, 활용신청, 호출과 변경 추적을 담당한다.

이 추천의 확신도는 **중간**이다. 문제·법적 구매 계기·실시간 공공데이터는 강하지만, 실제 지불의사와
현장 센서 도입 마찰은 아직 검증되지 않았다. 특히 법령상 체감온도는 작업장소에서 정해진 방식으로
측정한 값이다. 5km 공공 예보는 사전 경보와 현장 우선순위에는 쓸 수 있지만 법정 조치 여부를 대신
판정할 수 없다.

차선은 **통합돌봄 공급공백·배치 인텔리전스**, 그다음은 **공공조달 go/no-go·가격·파트너 분석**이다.

## 선정 방법

시장 규모의 그럴듯한 추정치보다 다음 다섯 질문을 우선했다.

1. 2026년에 문제를 미룰 수 없게 만드는 법·예산·운영 변화가 있는가.
2. 사용자가 아니라 실제로 돈을 낼 조직이 특정되는가.
3. 필요한 공공데이터가 제목만 존재하는 것이 아니라 파일 또는 호출 가능한 계약으로 열려 있는가.
4. 정부 무료 서비스와 기존 업무를 대체하고도 남는 유료 결과물이 있는가.
5. odeduck의 `discover → inspect → apply → call`이 반복 운영에서 실질적인 이점을 만드는가.

### 문제가 크고 2026년에 더 급해졌다

질병관리청의 완결된 2025년 응급실 감시 결과는 온열질환자 4,460명, 추정 사망자 29명이다. 2023년
2,818명, 2024년 3,704명에서 계속 늘었고, 2025년 환자의 32.1%인 1,431명이 실외 작업장에서
발생했다. 다만 이 수치는 참여 응급실 감시자료이며 산재 승인 건수나 전체 노동자 피해 전수조사는
아니다. 시장 규모로 그대로 환산하면 안 된다. [질병관리청 2026년 발표](https://www.kdca.go.kr/bbs/kdca/42/311060/artclView.do)

2025년 7월 17일 개정된 안전보건규칙은 폭염작업을 `별표 13의2에 따라 측정한 체감온도 31℃ 이상인
작업장소에서의 장시간 작업`으로 정의한다. 체감온도 33℃ 이상이면 원칙적으로 매 2시간 이내에 20분
이상의 휴식을 주도록 했다. 냉방·통풍 또는 보냉장구를 통한 예외도 법문에 있으므로, 제품이 법률문구를
단순한 단일 임계값으로 축약해서는 안 된다. [제559조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029039861),
[제560조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0560&lsiSeq=273603&urlMode=lsScJoRltInfoR)

고용노동부는 2026년 대책에서 이 조치를 법적 의무로 다시 명시하고, 폭염 취약사업장 1,000개소 불시
감독, 민간재해예방기관을 통한 14만 개소 기술지원, 일터지킴이 1,000명 운영을 발표했다. 건설뿐 아니라
물류·택배, 조선, 공공 발주공사와 공공근로를 중점 업종으로 열거했다. 이는 전체 잠재고객 수가 아니라
정부가 실제 현장 이행을 강화한다는 구매 계기다. [고용노동부 2026년 폭염 대책](https://moel.go.kr/news/enews/report/enewsView.do?news_seq=19380)

### 고객과 지불주체

첫 고객은 개별 영세 현장이 아니라 **20개 이상 현장을 책임지는 본사·원청의 안전보건 책임자**로
한정한다. 우선순위는 건설 원청, 물류센터·택배 허브 운영사, 시설관리사, 옥외 공공업무 수탁사다.
이들이 지불할 이유는 기상정보 자체가 아니라 다음 결과다.

- 어느 현장이 언제 위험할지 미리 정렬해 인력·작업시간을 조정한다.
- 현장 측정값이 기준을 넘으면 승인된 조치 템플릿을 배포하고, 미확인 현장만 에스컬레이션한다.
- 조치 시각, 원천 데이터, 센서값, 관리자 승인과 작업자 확인을 한 묶음으로 내보낸다.
- 본사가 20개 단톡방과 엑셀을 뒤지는 시간을 줄이고 누락 현장을 즉시 본다.

보험사·안전보건대행기관은 나중의 채널 가설이지 최초 구매자로 가정하지 않는다. 보험료 절감이나 법적
면책 효과는 현재 자료로 입증되지 않았으므로 영업 문구로 쓰지 않는다.

### 만들 제품과 만들지 않을 제품

최초 제품은 폭염 한 가지 위험만 다룬다.

```text
odeduck 공공데이터 계층
  ├─ 단기·초단기 예보 / 기상특보 / 과거 폭염·산재 데이터
  ├─ API 계약·필수 인자·승인상태·출처·갱신시각
  └─ 원천 변경 감지와 재현 가능한 호출
              ↓
고객 운영 계층
  ├─ 사업장 좌표·작업계획·책임자
  ├─ 현장 온습도계/센서 측정값
  ├─ 사람이 승인한 규칙과 조치 템플릿
  ├─ 알림·지시·확인·미응답 에스컬레이션
  └─ 원천·측정·행동 타임라인 PDF/CSV
```

공공 예보만으로 `준수/위반`을 자동 판정하지 않는다. 제품 화면에는 예보와 현장 측정을 분리해 표시하고,
법령 원문·데이터 시각·사람의 최종 승인자를 함께 보존한다. 임상 예측, 법률 자문, 근로자 개인 건강
프로파일도 MVP에서 제외한다.

확인이다. 이것이 제품의 결함이 아니라 고객 운영과 결합해야 생기는 유료 데이터다. 반대로 이 입력을
얻지 못하면 사업도 성립하지 않는다.

`15085288 생활기상지수 조회서비스`는 제목만 보면 체감온도 핵심 API처럼 보이지만, 이번 odeduck
`inspect`가 확인한 현재 operation은 자외선지수와 대기정체지수였다. 따라서 제목 검색 결과를 곧바로
제품 의존성으로 채택하지 않는다. 이 사례 자체가 검색 이후 실제 계약 검사가 필요한 이유다.

### 경쟁과 대체재 경계

기상청은 지역별 폭염 영향예보와 행동요령을 카카오톡으로 직접 제공한다. 무료 알림 앱은 이 서비스를
이길 이유가 없다. [기상청 폭염 영향예보 직접 전달 서비스](https://www.kma.go.kr/kma/news/press.jsp?bid=press&from=2025-03-06&mode=view&num=1194480&page=2&to=2025-06-06)

고용노동부의 무료 점검표, 14만 사업장 기술지원과 현장 감독도 강한 대체재다. 따라서 차별화 단위는
콘텐츠나 체크리스트가 아니라 여러 사업장의 작업계획과 현장 측정, 책임자별 이행상태를 연결한
**실행·증빙 시스템**이어야 한다. 법령 개정은 수요를 만들지만 동시에 무료 공급도 늘린다.

해자는 공공 API 접근권이 아니다. 시간이 지날수록 쌓이는 `현장별 예보 오차`, `센서 측정`, `어떤
조치가 실제 승인·이행됐는지`, `고객별 승인 흐름`과 원천 변경에도 재현 가능한 provenance가 방어력이다.

지도는 만들 수 있지만, 실제 빈자리·방문 가능시간·대기자·직원 근무표는 공개되지 않는다.

그래서 개인 환자 배정이나 지자체 사례관리 시스템이 아니라, 다지점 재가요양·방문간호·주야간보호
사업자의 출점·채용·제휴 우선순위를 첫 상품으로 삼아야 한다. 정부도 통합돌봄 정보연계와 지역 공급
조사를 추진하고 있어 공공부문 정면 경쟁은 피해야 한다. [보건복지부 2단계 실행방안](https://www.mohw.go.kr/gallery.es?act=view&bid=0003&list_no=379902&mid=a10606030000&tag=),
[통합지원기관 지정](https://www.mohw.go.kr/board.es?act=view&bid=0027&list_no=1488986&mid=a10503010100)

1순위가 아닌 이유는 구매자가 분산돼 있고, 핵심 capacity를 고객에게 다시 받아야 하며, 정부가 직접
비슷한 정보 기반을 구축하기 때문이다. 반면 고령화와 정책예산의 지속성은 가장 강하다.

## 차선 2: 공공조달 go/no-go·가격·파트너 분석

2025년 공공조달 실적은 238.5조원으로 역대 최대였고, 나라장터 거래는 145.8조원이었다.
[조달청 2025 공공조달 통계](https://www.pps.go.kr/kor/bbs/view.do?bbsSn=2606260005&key=00634)
2026년 나라장터 등록 조달계획은 85.6조원이며 약 80%가 상반기 집행 예정이었다.
[조달청 2026 조달계획](https://www.pps.go.kr/kor/bbs/view.do?bbsSn=2602120009&key=00318)

[입찰공고 API `15129394`](https://www.data.go.kr/data/15129394/openapi.do?recommendDataYn=Y),
[계약 API `15129427`](https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15129427),
[발주계획 API `15129462`](https://www.data.go.kr/data/15129462/openapi.do)는 실제로 열려 있고,
입찰공고 API는 자동승인·실시간 제공이다. 데이터 접근성과 반복 입찰기업이라는 지불주체는 세 후보 중
가장 명확하다.

그러나 차세대 나라장터 자체가 지능형 검색, AI 상품추천과 조달비서를 제공한다.
[조달청 차세대 나라장터](https://www.pps.go.kr/kor/content.do?key=01297) 따라서 범용 키워드 알림은
사업이 아니다. 한 업종에서 `참가 적합성`, `과거 낙찰률·가격`, `부적격 사유`, `공동수급 파트너`를
합쳐 실제 bid/no-bid 결정을 개선할 때만 유효하다. 데이터는 가장 좋지만 경쟁 방어력이 약해 3순위다.

## 나머지 후보를 내린 이유

- **건물 리트로핏:** 2026년 민간 그린리모델링 이자지원이 3년 만에 재개됐고 2014~2023년 약 8만 건을
  지원했다. [국토교통부 공식 안내](https://www.greentogether.go.kr/gpi/Green-News-View.do?greenNewsId=3866)
  [건물에너지 API `15135963`](https://www.data.go.kr/data/15135963/openapi.do)와
  [건축물대장 API `15134735`](https://www.data.go.kr/data/15134735/openapi.do)는 좋지만, 소유자 연락처,
  개보수 의사와 실제 고지서가 없다. 공개 데이터만으로 만든 고효율 리드는 납품 가능한 결과가 아니다.
- **공공·인프라 기후적응:** 지정 취약기관은 5년 대책과 연간 이행실적을 제출해야 한다.
  [탄소중립기본법 제41조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1019778895) 그러나 공식
  안내상 지정기관은 62개이고 정부가 지침과 VESTAP 도구를 무료 제공한다.
  [국가기후위기적응센터](https://kaccc.kei.re.kr/home/menu.es?mid=a10303030100) 고단가 컨설팅 결합형
  틈새는 가능하지만 독립 SaaS의 초기 고객 풀이 좁다.
- **상권 조기경보:** 서울시 상권분석서비스가 이미 뜨는 상권 순위와 점포·매출·유동인구·상주인구
  분석을 무료 제공한다. [서울시 상권분석서비스](https://golmok.seoul.go.kr/commercialArea/commercialArea.do)
  임대차 원장·건물주·실제 공실 같은 비공개 데이터 없이 공개 데이터만 재포장하면 차별화가 약하다.

## 단계형 검증 실험

2026년 범정부 폭염대책 기간이 9월 30일까지이므로 지금 바로 검증할 수 있다.

### 1단계: 7일 접촉, 21일 발견 인터뷰

1. 노무·산업안전 전문가에게 제559조·제560조와 별표 13의2를 기준으로 의사결정표를 검수받는다.
2. odeduck으로 `15084084`, `15000415`를 활용신청·표본 호출하고, 원천 시각과 누락·지연을 기록한다.
3. 중견 건설 원청 30곳에 연락해 7일 안에 인터뷰 일정 10건을 잡고, 21일 안에 실제 인터뷰 10건,
   최근 폭염일 기록 walkthrough 3건, 섀도 후보 2곳을 확보한다.
4. 실제 대화방·엑셀·점검표를 보며 담당자, 시간, 누락과 재작업을 재구성한다. 의견과 무상 LOI는 직접
   수요 증거로 계산하지 않는다.

### 2단계: 최대 30일 사후비교형 shadow test

같은 업종의 두 조직에서 각 10개 현장을 표본으로 삼는다. 고객은 기존 절차로 위험 선정·측정·판단·지시를
먼저 수행하고, 컨시어지는 고객 소유 저장소에서 가명 이벤트를 전사한다. odeduck/KMA 후보는 업무 종료
뒤에만 비교하며 당일 안전업무에 영향을 주지 않는다. 새 서버·공개 폼·제품 코드는 만들지 않는다.

종료 목표는 조직별 `closed loop` 10개 이상, 전체 30개 이상, 실제 적격 위험일 3일이다. 실제 위험일이
부족하면 historical replay로 데이터·증빙 흐름만 검증하고 실시간 운영 품질은 미검증으로 남긴다.
미측정 작업블록의 초과 여부를 관찰할 상시 기록이나 승인된 독립 측정 표본이 없으면 자동 위험 우선순위는
후속 제품 범위에서 제외한다.

### 3단계: 구매행동과 결제

최소 제품을 만들려면 두 조직 모두 실제 현장·담당자·임원 스폰서·구매 담당자를 제공하고 유료 조달
절차와 일정을 확인해야 한다. 동시에 실제 업무에서 `overdue·재작업 10% 이상`, `본사 수작업 주 4시간
이상`, `감사 가능한 기준 초과 누락 1건 이상` 중 하나의 고통이 관찰되어야 한다.

30만~100만원은 시장가격이 아니라 초기 지불의사 가설이다. 실제 전사·예외처리 시간, 전문가 검수,
인프라·보안비를 계산해 직접원가와 지원 상한을 먼저 정한다. 최소 제품 게이트를 통과한 뒤 60일 안에
독립 조직 두 곳의 입금 또는 취소 불가 발주서를 확보해야 상업성을 통과한다.

세부 상태, 보안, 지표 분모, 실패 처리와 구현 게이트는
`docs/designs/multisite-heat-safety-shadow-pilot.md`를 기준으로 한다.

## 명시적 반증 조건

다음 중 하나가 확인되면 1순위 가설을 중단하거나 바꾼다.

1. 21일 안에 실제 기록 walkthrough 3건과 같은 업종 섀도 후보 2곳을 확보하지 못하거나, 최소 제품
   게이트 뒤 60일 안에 유료 배포가 2곳 미만이다.
2. 공공 5km 예보와 현장 측정의 `33℃ 이상/미만` 분류가 위험시간의 20% 이상에서 달라지는데 센서
   결합 비용을 고객이 부담하지 않는다. 이 경우 public-data-only 제품은 폐기한다.
3. 고객 법무·노무팀이 자동 지시가 책임을 줄이지 않고 잘못된 준수 판정을 만든다고 판단한다. 이 경우
   자동 판정을 없애고 원문·측정값·사람 승인 중심 도구로 제한한다.
4. API 지연·변경으로 위험 이벤트 원천을 재현하지 못하거나, 데이터 이용조건이 상용 증빙 저장을
   허용하지 않는다.
5. 폭염 종료 뒤 갱신 의향이 절반 미만이고 한파·호우·대기질로 같은 워크플로를 확장해도 구매빈도가
   생기지 않는다. 계절성 ARR 가설을 폐기한다.

## 90일 범위와 최종 판단

첫 90일에는 한 업종, 20~50개 현장, 폭염 한 가지, 기상 API 두 개와 현장 센서 한 종류만 지원한다.
개인 건강정보를 받지 않고, 고객마다 승인된 조치 문구를 사용하며, “법적 준수 보장”을 판매하지 않는다.
최소 한 조직의 유료 갱신 또는 두 번째 실제 위험기간 반복 구매가 확인될 때만 한파·호우·대기질을 같은
실행·증빙 모델에 추가하고, 이후에만 공공자산 기후적응 연간 보고로 확장한다.

따라서 지금의 최선은 대규모 플랫폼 개발이 아니라 **30곳 접촉 → 실제 기록 인터뷰 → 두 조직의
사후비교형 shadow test → 유료 조달 착수**를 순서대로 검증하는 것이다. 이어 60일 안에 두 곳의 실제
결제와 이후 한 곳의 갱신까지 확인될 때만 odeduck을 범용 공공데이터 도구에서 반복 가능한 현장
의사결정 인프라로 확장할 근거가 생긴다.
