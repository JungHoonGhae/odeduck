# 공공데이터 사업 1순위 재검토: 공공입찰 의사결정 지원

조사일: 2026-09-07 (KST). 상태: 검증 진행. 제품 구현·고객 접촉·활용신청·인증 호출은 하지 않았다.

## 1. 결정과 확신

현재 오데덕의 접근 가능성과 첫 유료 검증까지의 거리를 기준으로, **공공입찰 참여 판단 지원**을
첫 검증 대상으로 선택한다. 이미 상품화된 대표 사례는 비드프로, 아이건설넷이며 AI 직접 경쟁사는
나입찰이다. 인지도·점유율 순위가 아니라 공개 제품과 요금 등 확인 가능한 근거로 사례를 선택했다.

결정 질문: 소규모 IT 유지보수·SI 기업의 대표 또는 영업 책임자가 새 용역 공고를 검토할 때,
기존 포털·유료 서비스·직원 검토에 추가로 돈을 내고 회사별 참여/보류/포기 근거표를 구매하는가?
유료 상품의 존재에는 높은 확신, 데이터 연결 계약에는 중간 확신, 우리의 추가 지불의사에는 낮은 확신이다.
납부 고객 수·매출·시장 전체 최상위 사업이라는 주장은 확인하지 못했다.

[9월 4일 조사](deep-monetizable-cross-domain-opportunity-2026-09.md)의 식품 공급사 사건/CAPA
우선순위를 폐기하지 않는다. 당시의 교차 분야 차별화 잠재력과 이번의 짧은 첫 매출 검증은 평가 기준이
다르다. 식품 쪽도 SafetyChain이라는 직접 대체재가 있으며 고객 원장 확보가 필요하다.
공공조달 역시 매우 혼잡하다. **조달 단계 연결이나 회사별 참가 판단 자체를 새 시장으로 주장하지 않는다.**

## 2. 구매자와 바뀌는 행동

- 구매자 가설: 반복적으로 공공 용역 입찰을 검토하는 소규모 IT 유지보수·SI 기업의 대표/영업 책임자.
- 사용자: 영업·제안 담당자. 촉발 사건: 신규 공고 또는 정정 공고, 가까운 제안 마감.
- 현재 대안: 나라장터 직접 확인, 직원의 공고/첨부/실적표 대조, 기존 입찰 서비스.
- 손실 가설: 맞지 않는 공고에 제안 인력을 배정하거나 변경된 조건을 뒤늦게 발견한다. 빈도·금액 미측정.
- 판매할 결과: 출처·기준 시점·누락 조건이 있는 참여/보류/포기 검토표. 최종 결정은 고객 담당자가 한다.

## 3. Before / after

현재 업무 가설: 공고 발견 → 첨부 읽기 → 회사 자격·실적 대조 → 과거 계약 검색 → 대표 승인.
검증할 흐름: 회사 자료 제공 → 관련 공고 발견 → 공식 번호로 이력 연결 → 조건별 근거/미확인 표시 → 사람 승인.
절약 시간만으로 성공 처리하지 않는다. 실제 제안 인력 배정 또는 참여 결정이 더 나아져야 한다.
낙찰 확률 보장, 자동 투찰, 법적 참가자격 인증, 개인정보 수집을 제품 범위에 넣지 않는다.

## 4. 데이터 연결 계약과 누락

실행한 검색: `go run ./cmd/odeduck catalog search '나라장터 입찰공고 낙찰 계약 발주계획' --limit 6 --require-semantic`.
종료 0, hybrid 및 `embeddinggemma:300m-qat-q4_0` 의미 검색 사용을 확인했다.
반환 PK: 15129459, 15053346, 15129462, 15049656, 15053351, 15129394.
이는 카탈로그 발견 증거이며 실제 업무 효용이나 행 단위 연결 성공 증거가 아니다.

아래 네 건은 `go run ./cmd/odeduck inspect <PK> --format json`으로 각각 검사했고 모두 종료 0이었다.
REST, 공식 Swagger operation, 개발/운영 자동승인 명세를 확인했다. 실제 업무 레코드 호출은 하지 않았다.

| 원천 | 확인된 조회 계약 | 고객 결정 / 남은 경계 |
| --- | --- | --- |
| [15129459 계약과정통합공개](https://www.data.go.kr/data/15129459/openapi.do) | `bidNtceNo`, `bidNtceOrd`, `bfSpecRgstNo`, `orderPlanNo`, `prcrmntReqNo` | 조달 단계의 원천 연결을 재사용한다. 공식 설명도 단계·번호 누락을 경고한다. |
| [15129394 입찰공고정보](https://www.data.go.kr/data/15129394/openapi.do) | 공고번호 조회와 업무별 operation, 변경 관련 명세 | 조건 확인의 출발점. 첨부 해석·최신 정정 반영의 완전성은 미검증이다. |
| [15129462 발주계획현황](https://www.data.go.kr/data/15129462/openapi.do) | `orderPlanUntyNo`, `orderInsttCd`, 조회 기간 | 선행 영업 후보. 통합공개의 `orderPlanNo`와 이름이 다르므로 동일 값이라고 추정하지 않는다. |
| [15129427 계약정보](https://www.data.go.kr/data/15129427/openapi.do) | `untyCntrctNo`, 계약 변경이력 operation | 구매기관의 과거 계약 근거. 통합공개 응답의 계약 식별자와 실제 매핑을 검증해야 한다. |
| 고객 제공 자격·실적·가용 인력 자료 | 아직 확보하지 않음 | 핵심 누락 edge. 회사 이름 유사도로 자격·실적을 귀속하지 않는다. |

접근: 통합공개 공식 페이지는 무료·이용허락범위 제한 없음, 개발 트래픽 1,000으로 표시한다.
표시 숫자의 기간 단위·증량 승인·호출 안정성은 별도 확인 대상이다. 명세 열람에는 로그인이 필요 없었다.
범위: 통합공개는 물품/외자/용역/공사를 설명하지만 기관·시간 모집단과 실제 행 수는 미확인이다.
입찰공고 페이지에서 관찰한 시간범위는 1995년 10월–2025년 1월인 반면 수정일은 2026-06-29였다.
따라서 최신 레코드 포함·실시간 갱신·공개 지연을 메타데이터 수정일로 보증하지 않는다.

그래프 경계: Source는 제공기관/공식 계약, Record는 원문 버전, Entity는 출처 namespace가 있는
공고·기관·계약, Claim/Event는 특정 버전의 조건·정정·체결이다. 원문을 canonical entity로 덮어쓰지 않는다.
원천 URL, operation/조회 범위, 수집 시각과 사건 유효 시각을 분리한다. 정정 전후를 보존한다.
공식 번호 관계는 실제 응답 대조 전까지 계약 수준 근거이며, 이름·임베딩 유사도는 후보 제안만 한다.
서로 다른 번호의 deterministic 변환은 공식 매핑 근거와 표본 검증 없이는 만들지 않는다.

| 실제로 답해야 할 질문 | 시작점 → 필요한 경로 | 시간·오탐 경계 |
| --- | --- | --- |
| 우리 회사가 검토할 공고인가? | 회사 수행 분야 → 의미 후보 → 공식 공고 | 의미 유사도는 자격 충족이 아니다. |
| 이 조건을 충족하는가? | 최신 공고 조건 → 고객 증빙 → 조건별 주장 | 마감 기준 증빙 유효기간 확인, 미확인은 보류. |
| 조건이 바뀌었는가? | 공고번호·차수 → 정정 이력 → 최신 원문 | 차수·취소·재공고를 합치지 않는다. |
| 이 기관은 관련 과업을 실제 계약했는가? | 기관의 공식 식별자 → 과거 계약 → 과업 원문 | 동명 기관·회사 배제, 계약 미발견은 계약 없음이 아니다. |
| 이 발주계획이 지금 공고로 이어졌는가? | 계획 번호 → 공식 통합공개 관계 → 공고 | 번호 체계 매핑 미검증이면 연결 보류. |

현재 필요한 것은 검증 가능한 연결과 고객 결정 기록이지 그래프 DB 도입이 아니다.

## 6. 지불 증거와 모르는 수치

현재 증거는 3등급(경쟁사의 공개 가격)이다. 독립 구매자의 지불·발주서(1등급)와 실제 업무 화면 및
고객 데이터 제공(2등급)은 없다. 건설 중심 요금 사례를 IT 기업의 지불의사로 전용하지 않는다.
우리 정가, 고객별 손실, 원가, CAC, LTV, 갱신률, 시장점유율은 미정이다.
판매 모델 가설은 초기 수작업 유료 검토 후 반복 수요가 확인되면 구독으로 전환하는 것이다.
견적은 실제 처리 범위·검토 인건비를 산출해 제시하며 경쟁사 요금만으로 정하지 않는다.

기간: 2026-09-08~2026-09-21. 사용자 승인 후 창업자가 기존 지인 소개 또는 기업 공개 영업 연락처로
해당 구매자 10곳에 접촉한다. 연락은 이번 조사에서 보내지 않았다.
최소 5곳에서 최근 실제 검토 화면과 현재 지출을 확인하고, 독립 2곳에서 사용 동의를 받은 회사 자격·실적,
검토 결과와 공고번호를 확보한다. 민감한 원장은 공개 문서·로그에 남기지 않는다.

과거 공고 100건을 최소 2개 고객과 재생하고 기존 도구+사람 방식과 같은 입력으로 비교한다.
정답셋은 고객 담당자가 원문으로 판정한다. 동명 기관/회사, 다른 차수, 재공고, 취소, 만료 증빙,
변경·삭제 계약, 누락 레코드를 hard negative로 포함한다. 과거 결정 시점 이후 자료는 정답 입력에서 제외한다.

- 연결 확정의 정밀도 99% 이상, 잘못된 자격 충족 판단 0건. 모든 최종 참여 결정에는 사람 승인.

- 기존 방식 대비 검토 시간 중앙값 30% 이상 절감 및 고객이 인정하는 올바른 참여/보류 결정 변경 2건 이상.
