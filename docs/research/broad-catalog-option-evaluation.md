# API + FILE 통합 카탈로그 스모크 평가

평가일: 2026-09-01

## 질문

OpenAPI만 검색할 때보다 FILE까지 같은 카탈로그에 넣는 것이 실제로 새로운 조합 선택지를 제공하는가?
최종 connection 수를 늘리지 않고 역할별 option pool을 두어도 탐색 폭을 넓힐 수 있는가?

## 환경

- 기존 사용자 스냅샷: 2026-08-31 API 11,902건
- 격리된 신규 ALL 스냅샷: 2026-09-01 고유 노드 95,956건
  - REST 7,132
  - LINK 4,766
  - FILE 84,052
  - 미확인 6
- ALL 동기화: 429초
- `catalog.json`: 약 99MB
- ALL lexical 검색: `장기요양기관 평가`, 20건 제한, 약 0.78초
- 이 최초 비교에서는 semantic 인덱스를 사용하지 않음. 이후 95,951건 전체 인덱스 실측은
  [통합 시맨틱 인덱스 평가](integrated-semantic-index-evaluation.md)에 분리해 기록함

두 스냅샷의 시점이 하루 다르고 현재 API 스냅샷에 두 항목이 더 있으므로 정밀 검색 benchmark가 아니라
기능 스모크 비교다.

## 동일 질의 결과

질의: `장기요양기관 평가`

### API 전용

1건만 반환했다.

- `15009684 서울특별시 관악구_공공시설개방정보` — 단어는 description에서 일치하지만 장기요양 평가
  분석의 직접 데이터가 아니다.

### API + FILE

5건을 반환했다. 그중 다음 세 항목은 API 전용 결과에서 보이지 않던 직접적인 분석 재료다.

- `15104801 국민건강보험공단_장기요양기관 평가 결과` — 2021~2025 정기평가 결과
- `15127484 국민건강보험공단_장기요양기관 평가 5회 이상 A를 받은 기관 현황` — 반복 우수기관
- `15124194 국민건강보험공단_장기요양기관 평가년도 평가등급별 기관수 및 수급자수` — 평가등급별
  기관·수급자 집계

`15043855 전남광주통합특별시_노인요양시설 현황`은 인접한 시설 공급 데이터이고,
`15009684`는 기존과 같은 노이즈였다. 즉 이 한 질의에서는 결과 수가 1→5로 늘었을 뿐 아니라,
직접 쓸 수 있는 평가 데이터가 0→3으로 늘었다.

FILE 검색 결과는 공식 `detailUrl`, formats와 `nextAction`을 반환했다. 포털 목록의 `JSON + XML`
badge도 자동변환 표현의 존재로 보존하지만 `/openapi.do` 계약이 확인된 것은 아니므로 현재
`call_api` 대상으로 승격하지 않는다.

## 조합 풀 검증

고정 fixture에서 표시 결과 limit을 2로 두고도 두 Bridge 역할에 각각 두 대안을 보존했다.

- 지역 수요: 장기요양 인정자 API, 고령인구 전망 FILE
- 부동산 제약: 건축물대장 API, 토지이용계획 FILE

`connectionOptions`에는 네 노드가 남았지만 explicit `bridgeSelections` 전에는 connection card가
생기지 않았다. hybrid fixture에서는 lexical query에 직접 맞지 않고 semantic으로만 회수된 Bridge도
option pool에 들어왔고, 기존 selection/evidence gate를 통과한 뒤에만 최종 candidate가 됐다.

## 결론

FILE 통합은 단순히 데이터 수를 늘리는 변화가 아니다. API 카탈로그에서 실제로 누락되던 분석축을
회수해 조합 선택지를 만든다. 다만 8만여 FILE을 모두 최종 카드로 만들면 노이즈와 컨텍스트가
폭발하므로 다음 두 표면을 계속 분리한다.

- 넓은 표면: 역할별 최대 3개, 전체 최대 21개의 `connectionOptions`
- 정밀 표면: 사용자가 명시적으로 고른 최대 3개의 `connections`, 상태는 항상 `candidate`

다음 품질 평가는 여러 봉인 질의에서 API-only와 ALL의 Recall@k, role coverage, option precision,
FILE 다운로드 성공률을 동일한 스냅샷 시점으로 비교해야 한다.
