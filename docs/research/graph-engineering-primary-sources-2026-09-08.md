# 그래프 엔지니어링 재검토: 1차 자료와 최소 도입 기준

확인일: 2026-09-08 (Asia/Seoul). 상태: 설계 제안, 구현·성능 검증 아님.
범위: [INTENT.md](../../INTENT.md)의 먼 데이터 연결 목표에 필요한 외부 연구 근거.
제품 완료 판단은 [완료 감사표](../specs/goal-driven-completion-plan.md)를 유지한다.
로컬 구현 감사와 대통령 관련 실조회 결과를 이 문서가 대신하지 않는다.

## 결론

**먼 분야를 찾는 검색과, 찾아낸 관계가 사실인지 검증하는 기능을 분리한다.** 전자는 반복 검색과
탐색 범위 확장, 후자는 식별자·원천 행·시간·연결 규칙의 문제다. GraphRAG 패키지나 그래프 DB를
추가하는 것만으로 후자가 해결된다는 근거는 찾지 못했다. 기존 저장소에서 bounded join과 검증 가능한
claim을 우선 완성하고, 비교 평가가 필요성을 보일 때만 새 검색·저장 기술을 검토한다. 이는 아래
자료에 대한 오데덕 적용 판단이며, 특정 기술이 모든 환경에서 불필요하다는 결론은 아니다.

논문은 저자 제공 초록과 버전 메타데이터를 확인한 범위다. 세부 실험을 재현하지 않았으므로 수치
우월성·비용 절감률을 제품 설계의 통과선으로 쓰지 않는다. 공식 문서는 변경 가능한 페이지다.

## 답해야 할 다섯 질문

아래는 실제 사실을 주장하는 예시가 아니라, 원천 확보 후 고정할 검증 질문이다. 대통령 개인의
사적 관계나 의혹을 이름·지역·동시 출현만으로 만들지 않는다. 탐색 후보에는 불확실성을 표시하고,
사용자에게 확정 사실로 제시하는 출력에는 확인된 오탐을 허용하지 않는 시험 기준을 둔다.

| 질문 / 사용자 산출물 | 시작점 → 허용 경로 | 시간·오탐 기준 | 최소 실행 방식 |
| --- | --- | --- | --- |
| 대통령의 공개 행사와 관련 문화시설에 뜻밖의 공통점이 있는가? / 근거 있는 사실 카드 | 공식 행사 record → 명시된 장소 → 시설 record | 행사일의 시설 정체성 확인; 같은 장소명이면 unresolved | 장소 식별자·공식 대응표의 2단계 join |
| 서로 다른 시기의 대통령이 방문한 같은 시설이 있는가? / 방문 비교표 | 행사 record → 동일 시설 ← 다른 행사 record | 사건일과 공개일 분리; 동명 시설·이전 주소 오인 차단 | 기간 필터와 시설별 집계 |
| 대통령 관련 기념물과 다른 문화유산은 같은 인물의 작품인가? / 작품 연결 카드 | 기념물 record → 명시된 제작자 → 다른 작품 record | 동명이인·공동제작자·복원자 혼동 차단; 이름만으로 확정 금지 | 제작자 원천 식별자가 없으면 후보로 중단 |
| 대통령 관련 공공행사를 수행한 기관의 다른 공개 계약은 무엇인가? / 기관 활동표 | 행사 record → 명시된 수행기관 → 계약 record | 기관 법적 범위·당시 명칭 확인; 계약 관계를 친분·특혜로 해석 금지 | 발급기관이 같은 기관 ID로 bounded join |
| 찾은 연결을 정정 자료가 뒤집는가? / 현재 근거와 정정 이력 | 결과 claim → 근거 record → 대체·취소 record | 원래 유효 시점과 나중 관측 시점 분리; 일부 조회의 미발견을 부재로 표현 금지 | claim revision과 원천 재조회 |

이 질문들의 원천이 data.go.kr 범위에서 없으면 coverage 부족이다. 외부 웹에서 발견한 이야기를
오데덕 실행 결과로 표시하거나, 답이 나오는 질문으로 몰래 바꾸는 것은 평가 성공이 아니다.

## 최소 계약: 새 온톨로지보다 증거 경계

그래프 스킬의 기존 네 층을 그대로 사용한다. Source는 제공기관·dataset·revision, Record는 그
원천의 행 ID 또는 hash, Entity는 여러 record가 가리키는 대상, Claim/Event는 원천이 특정 시점에
보고한 관계·사건이다. 이 문서는 새 도메인 용어나 영구 저장 결정을 확정하지 않는다.

| match 등급 | 필요한 근거 | 소비 가능한 범위 |
| --- | --- | --- |
| exact | 발급기관·namespace·유효 기간이 같은 식별자 | 그 식별자의 대상 범위에 한정한 연결 |
| deterministic | 버전 고정 대응표 또는 재현 가능한 복합 조건 | 해당 규칙의 검증 범위 내 연결 |
| probabilistic | 이름·문맥·embedding 등의 후보 점수와 원문 | 다음 검색·사람 검토; 확정 사실 출력 제외 |
| unresolved | 식별 근거나 시간·범위가 부족함 | 누락 이유와 다음 관측만 표시 |

각 확정 연결은 원천 record, 원문 필드 위치, 추출·정규화 버전, match 방법, 검토 상태,
`observedAt`, 확인 가능한 `validFrom/validTo`, 정정·대체 관계를 추적한다. 알 수 없는 시점은 unknown으로
남긴다. 이미 검증한 연결의 점수보다 그 연결을 만들었던 증거를 우선 재사용한다.
결과는 원천 hash/보존 가능한 위치로 재현하되, 인증키·불필요한 개인정보를 저장하는 수단으로 쓰지 않는다.

## 무엇을 지금 하고 무엇을 미룰 것인가

- 지금: 목표 → 후보 검색 → 실제 관측 → 관계 검증 → 부족한 근거의 재검색 → 출처 있는 산출물이라는
  한 실행 경로에서, 위 질문에 필요한 누락만 보완한다. 기존 장부·실행 상태가 이 경로에서 실제로
  소비되는지 먼저 확인한다. 후보 검색 유사도는 관계 사실의 저장 기준으로 사용하지 않는다.
- 지금: 결과 카드에는 사실, 경로, 출처, 사건 시점, 관측 시점, 남은 한계를 함께 표시한다. 목표의
  ‘놀라움’은 사실성을 통과한 뒤 사용자 유용성 평가에서 다룬다. 많은 연결 자체를 성공 점수로 삼지 않는다.
- 유보: 전 카탈로그의 LLM entity 추출·community summary 사전 생성, 전역 canonical entity 병합,
  범용 온톨로지, GraphRAG 프레임워크 교체, 그래프 DB. 필요 질의·실제 실패·비교 결과가 아직 선행해야 한다.
- 저장 전환 조건: 원천 근거가 갖춰진 뒤에도 반복적인 가변 길이 경로 질의가 실제 병목이고, 같은
  질문·데이터·정확도에서 현재 표/색인보다 측정 가능한 이득이 있을 때 별도 결정한다.

## 작은 비교 평가와 중단 기준

이 문서는 기존 M1–M5를 대체하는 새 개발 계획이 아니다. 현재 감사표의 I2/I5/I7/I8/I10을 확인할
제안이다. 위 다섯 질문마다 원천으로 답할 수 있는 양성, 동명이인 hard negative, 시점 불일치,
정정·취소, unresolved 사례를 고정한다. 기존 단일 검색과 관측 기반 반복 검색을 같은 원천·예산에서
비교하고, GraphRAG는 문서 코퍼스의 전역 요약 질문이 실제 필요할 때만 세 번째 비교군으로 둔다.

보고 항목은 후보 회수율, match 등급별 precision/recall, 원천까지 추적되는 출력 비율, 잘못된 사실
출력 수, 답할 수 있는 질문의 완료율, unknown/접근 실패 수, 시간·호출·토큰 비용이다. 모든 답을
review로 돌려 오류만 0으로 만든 시스템도 미완료다. 작은 시험의 오탐 0은 운영 정확도 보장이 아니다.
실패가 원천 부재·접근 차단이면 저장 기술 변경을 중단하고 그 의존성을 보고한다. 실패가 식별·시간
검증이면 해당 규칙을 먼저 고친다. 단순한 실행 경로보다 유용성·완료율 개선이 없으면 새 계층은 도입하지 않는다.
