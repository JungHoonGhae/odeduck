# 주제 선정 — 어떤 질문이 교차와 충격을 동시에 만족하나

Type: prototype
Status: open

## Question

목적지는 "과정과 결과가 둘 다 충격적"이다. 과정 쪽은 도구가 보장한다. **결과 쪽이 이 노력
전체의 최대 위험**이다: 여러 기관을 교차해야만 답이 나오는 질문은 만들기 쉽지만, 그 답이
**놀라운지는 계산해 보기 전까지 알 수 없다.** 평범한 답이 나오면 글이 없다.

어떤 질문을 던질 것인가?

## 조건 (셋 다 만족해야 함)

1. **교차가 필수** — 한 기관 API 하나로는 답이 안 나오고, 도메인이 다른 기관 2~3곳을 붙여야
   비로소 답이 되는 질문. (이것이 "AI가 스스로 뭘 신청할지 찾아냈다"를 성립시킨다.)
2. **결과가 반직관적** — 통념과 어긋나거나, 아무도 세어본 적 없는 숫자. 방향만 맞고 크기가
   시시하면 실패다.
3. **데이터가 실재하고 호출 가능** — 필요한 데이터셋이 전부 `svcType=REST` 여야 한다.
   LINK 가 하나라도 끼면 클린룸 실행에서 막힌다(`catalog search --rest-only` 로 확인).

## 왜 prototype 인가

종이 위에서 고를 수 없다. **기존 계정으로 후보 2~3개를 거칠게 계산해 보고**, 나온 숫자를
보고 반응해서 고르는 것이 유일한 방법이다. 여기서 만든 코드/노트는 버린다 — 남기는 것은
"어떤 질문을 던질지"라는 결정 하나다.

## 좋은 답의 모양

선택한 질문 + 그 질문이 요구하는 데이터셋 목록(pk, 기관, svcType=REST 확인됨) + 기존
계정으로 미리 계산해 본 답의 크기 + 왜 그 크기가 낯선 사람에게 충격적인지 한 문장.

## 참고

- 이전 세션의 소재: 폭염-인명피해 상관 r = -0.20(약함, 그대로는 약한 소재), 온비드 실시간
  경매. 둘 다 "교차" 조건이 약하다.
- 카탈로그는 활용신청 수를 담고 있다 — 수요가 몰린 데이터셋은 이미 남들이 본 것이므로,
  오히려 **덜 쓰이는데 교차하면 강해지는 조합**을 찾는 편이 낫다.
