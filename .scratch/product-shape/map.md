# Map: gongctl의 다음 형태

Label: `wayfinder:map`

## Destination

**gongctl이 무엇이 되어야 하는지를 증거로 결정한다** — 하나의 포털을 깊게 파는 도구로 남을지,
임의의 "접근 문"을 여는 일반 도구가 될지. 목적지는 결정과 그 근거이며, 구현이 아니다.
결론은 ADR 로 남겨 다음 세션들이 다시 논쟁하지 않게 한다.

핵심 가설:

> LLM 이 실제 데이터에 닿지 못하는 이유는 데이터가 없어서가 아니라, 그 앞에 가입·신청·승인·
> 키 발급이라는 **사람만 통과할 수 있는 문**이 있어서다. gongctl 은 그 문 하나를 뚫었다.
> 그 뚫는 방법이 일반화되면 제품이고, 안 되면 data.go.kr 유틸리티다.

## Notes

### 이미 결정된 것 (다시 논쟁하지 말 것)

- **소유 형태: 내가 계속 소유하는 오픈소스.** 남이 확장해주기를 전제하지 않는다.
  → 이 제약이 지도의 모양을 정한다: **넓이는 손으로 짠 어댑터 N개에서 나올 수 없다.**
  혼자 유지 가능한 것은 어댑터 39개가 아니라 일반 메커니즘 하나뿐이다. 어댑터 생태계
  아이디어는 이 제약과 충돌하므로, 살아남으려면 "어댑터가 극단적으로 얇다"가 증명돼야 한다.
- **스크래핑 유지**(ADR 0001) — 읽기 경로는 순수 서버렌더라 API discovery 로 얻을 게 없다.
- 이미 측정된 숫자는 재조사 금지: 오픈API 11,932 / REST 7,156 / LINK 4,770 / 미확인 6,
  LINK 제공기관 호스트 39개(표본 70, 최다 13%), 개발단계 심의 0건(표본 90),
  게이트웨이 전파 7~10분, 카탈로그 수집 약 160초.

### 이 지도가 쓰는 렌즈

- `/codebase-design` 의 deep module·seam 어휘로 "일반 메커니즘"의 경계를 잡는다.
- `/prototype` 은 버리는 코드다. 남기는 것은 결정뿐.
- steipete 렌즈("네 문제인가", "thin wrapper 인가", "2문장으로 설명되나")는 유효한 반증
  도구로 쓴다 — 통과 못 하는 방향은 지도에서 잘라낸다.

### 운영 규칙

- 한 세션에 티켓 하나(research 는 예외).
- subagent 는 사용자가 지시할 때만 띄운다. `research` 티켓은 인라인으로 풀어도 된다.

## Not yet specified

- **이름과 포지셔닝.** `gongctl`(공공)이라는 이름은 한국 공공데이터에 묶여 있다. 일반화가
  성립하면 이름이 발목을 잡는다 — 다만 성립 여부가 정해지기 전엔 논할 수 없다.
- **에이전트 표면의 재설계.** 일반화가 성립하면 MCP 툴 구성이 통째로 달라진다
  (`search_datasets` vs `catalog_search` 중복 정리도 여기에 흡수된다).
- **문서·배포 형태.** 어떤 형태든 "처음 5분"이 달라진다.
- **수익 경로.** 소유 형태를 오픈소스로 정했지만, 그것이 영원히 무료를 뜻하는지는 별개다.

## Out of scope

- **링크드인 글 / 바이럴 증명** — 별도 노력 `.scratch/viral-post/` 에 지도가 서 있다.
  제품 형태가 정해지면 그 지도의 목적지가 달라질 수 있으므로, 그때까지 멈춰 둔다.
- **기능 추가 일반** — MCP 툴 정리, 카탈로그 FILE 유형 등. 형태가 정해지기 전의 기능 추가는
  버릴 가능성이 있는 투자다. 단 `apply` 라이브 검증은 예외로 이 지도 안에 있다
  (일반화 실험이 그 코드 위에서 돌기 때문).
- **멀티포털을 손으로 짠 어댑터로 지원하기** — 소유 제약과 정면 충돌. 이 방향은 위 가설이
  기각되더라도 되살아나지 않는다.
