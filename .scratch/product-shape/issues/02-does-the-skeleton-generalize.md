# data.go.kr 이 특별한가 — 뼈대는 다른 문에도 통하는가

Type: prototype
Status: open
Blocked by: 03, 09

## Question

이 지도 전체의 크럭스. **gongctl 의 뼈대가 재사용되는가, 아니면 data.go.kr 전용인가?**

뼈대란 이것들이다:
1. 사람이 브라우저로 1회 로그인 → **세션 쿠키 추출 후 브라우저 종료**
2. 읽기는 순수 HTTP, 쓰기(신청)만 headless 브라우저에 세션 주입
3. 페이지의 **자기 자신의 제출 함수**를 구동(payload 를 재구현하지 않음)
4. 발급된 키를 계정 페이지에서 파싱해 호출에 주입
5. 승인/전파 상태를 목록에서 확인

## 검증 방법

다른 소스 **2~3곳**에 대해 접근 획득 절차를 실제로 밟아보고, 위 5단계 중 몇 개가 그대로
서는지 센다. 후보(도메인이 서로 다를수록 좋다):

- **서울 열린데이터광장** (`data.seoul.go.kr`) — 또 다른 공공 포털. 가장 가까운 이웃이라
  "공공 포털끼리는 통한다"의 하한선을 잡는다.
- **DART** (`opendart.fss.or.kr`) — 금융, 별도 가입·즉시 키 발급으로 알려져 있다.
  승인 대기가 없으면 gongctl 의 전파 대기 로직이 불필요해진다 → 뼈대가 과한지 드러난다.
- **카카오/네이버 developers** — 상업 플랫폼. **OAuth 앱 등록** 모델이라 문의 성격 자체가
  다르다. 여기서 뼈대가 깨진다면 "공공 포털 전용"이라는 경계가 드러난 것이다.

각 소스에 대해 기록할 것: 로그인 방식, 세션이 쿠키로 이동 가능한지, 신청/등록이 폼인지
API 인지, 키가 어디서 나오는지, 승인 대기가 있는지, **손으로 짠 코드가 얼마나 필요했는지.**

## 판정 기준 (미리 정해 둔다 — 결과를 보고 기준을 바꾸지 않기 위해)

- **일반화 성립**: 3곳 중 2곳 이상에서 5단계 중 4개 이상이 서고, 소스별 추가 코드가
  선언적 기술(경로·셀렉터 몇 줄) 수준.
- **부분 성립**: 공공 포털끼리는 서지만 상업 플랫폼에서 깨진다 → 경계를 "한국 공공 포털"로
  다시 긋는다. 이것도 유효한 결론이다.
- **기각**: 소스마다 뼈대가 다르게 필요하다 → 손으로 짠 어댑터 N개 외에 길이 없고,
  소유 제약상 넓힐 수 없다. data.go.kr 을 깊게 파는 쪽이 답이다.

## 왜 prototype 인가

문서를 읽어서는 알 수 없다. 실제로 가입하고 붙여봐야 한다. 만든 코드는 버린다 —
남기는 것은 위 판정 하나다.

## 왜 09 에도 막혀 있나

이 티켓은 이 지도에서 가장 비싼 실험이다(가입 3곳, 실제 붙여보기). 접근할 가치가 있는
데이터가 있다는 것이 먼저 서지 않으면, 성공해도 쓸 데가 없는 능력을 만들게 된다.
`09` 는 싸고 이 티켓을 죽일 수 있으므로 먼저 돈다.

## 주의

`apply` 라이브 검증이 끝나야 한다. 리팩터링된 코드가 원본 포털에서 도는지 모르는 상태로
다른 포털 실험을 하면, 실패했을 때 원인이 둘로 갈려 아무것도 배우지 못한다.
