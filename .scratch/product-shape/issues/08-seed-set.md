# 틀이 믿기려면 day-one 에 무엇이 돌아야 하나

Type: grilling
Status: open
Blocked by: 02, 05

## Question

틀만 던져두면 아무도 오지 않는다. **처음부터 동작하는 소스가 몇 개, 어떤 성격이어야**
낯선 개발자가 "여기에 내 것도 붙일 수 있겠다"고 생각하는가?

## 다툴 지점

- **개수.** 하나(data.go.kr)면 "그냥 그 포털용 도구"로 읽힌다. 둘이면 우연으로 읽힐 수 있다.
  셋부터 패턴으로 읽히는가? 근거 있는 숫자인가 아니면 느낌인가?
- **성격.** 같은 종류(공공 포털) 셋보다 서로 다른 종류(공공 / 금융 / 상업 플랫폼) 셋이
  "일반적"이라는 인상을 준다. 다만 다른 종류일수록 붙이는 비용이 크다. 어디서 균형인가?
- **누구를 향한 신호인가.** 기여자에게 "쉽다"를 보여주는 것과, 사용자에게 "쓸모 있다"를
  보여주는 것은 다른 seed set 을 요구할 수 있다. 둘 중 무엇이 먼저인가?
- **기여 경로가 문서로 존재하는가.** 소스가 셋이어도 "어떻게 넷째를 붙이는지"가 없으면
  아무도 시작하지 않는다. 그 문서는 언제 쓰는가?

## 왜 blocked 인가

어떤 소스가 실제로 붙는지(크럭스 프로토타입)와 어떤 소스가 약관상 가능한지(자세)를 모르면,
seed set 은 희망사항 목록이 된다.

## 좋은 답의 모양

day-one 에 동작해야 할 소스 목록과 그 선택의 근거, 그리고 "넷째를 붙이는 법" 문서가
언제 어떤 형태로 존재해야 하는지.
