# 웹 검색이 이미 충분한가 — A/B eval

Type: prototype
Status: open

## Question

이 제품의 진짜 대안은 경쟁 도구가 아니라 **"LLM 이 웹에서 알아서 찾아준다"** 이다.
소유자 본인이 그래서 시도조차 하지 않는다(→ `01`).

**웹 검색이 증명 가능하게 실패하는 질문의 계급이 존재하는가? 얼마나 큰가?**

## 형식: eval

같은 프롬프트를 두 팔에 넣고 산출물을 비교한다. 스킬을 만들 때 하는 그 eval 이다.

- **A (baseline)**: Claude + 웹 검색. gongctl 없음.
- **B (treatment)**: Claude + gongctl MCP.

일회성 비교가 아니라 **레포에 남는 하네스**로 만든다. 도구가 바뀔 때마다 다시 돌려
회귀를 잡고, 결과 자체가 공개 가능한 증거가 된다.

## 이 eval 이 스스로에게 유리해지지 않게 하는 장치

대충 만든 eval 은 우리에게 유리한 결과를 내놓는다. 그러면 없느니만 못하다.
다음을 설계에 박아 넣는다.

1. **베이스라인을 약하게 만들지 않는다.** A 는 웹 검색을 *제대로* 쓰는 Claude 다.
   검색을 막거나 힌트를 덜 주는 순간 실험이 아니라 연출이 된다.
2. **A 를 먼저, 오염 없이 돌린다.** B 의 답을 아는 상태로 A 를 돌리면 A 가 어디서
   틀렸는지 이미 알고 채점하게 된다. A 는 **B 를 돌리기 전에, 별도 세션**에서 받는다.
3. **판정은 주관적 우열이 아니라 체크 가능한 항목으로.** "어느 쪽이 낫나"는 자기 도구를
   채점하는 모델에게 물으면 안 되는 질문이다. 대신 사실로 답할 수 있는 것만 본다(채점표).
4. **정답의 출처를 미리 정한다.** B 의 답이 자동으로 진실인 것은 아니다. 1차 데이터를
   근거로 삼되 "B 가 그렇게 말했으니 A 가 틀렸다"는 논증은 금지한다. 불일치가 나오면
   원본을 직접 확인하고, 확인 불가면 **판정 보류**로 기록한다.
5. **질문 세트를 먼저 고정한다.** 결과를 보고 유리한 질문만 남기면 실험이 아니다.
   세트를 파일로 커밋한 뒤 실행한다.

## 질문 세트 (실행 전에 고정, 8~12개)

의도적으로 섞는다. **우리가 질 만한 것을 반드시 포함한다.**

- **대조군** — 웹에 답이 있을 법한 것. 여기서 B 가 이기면 설계가 틀린 것이다.
- **최신성** — 오늘/이번 주 수치. 기사화 주기보다 짧은 것.
- **교차** — 도메인이 다른 기관 둘 이상을 붙여야 나오는 수.
- **롱테일** — 아무도 기사로 쓴 적 없을 법한 행정 데이터.

질문을 만드는 일 자체가 `01` 에서 드러난 "던져지지 않은 질문"을 꺼내는 작업이므로
소유자와 함께 만든다.

## 채점표 (질문마다 두 팔 모두)

| 항목 | 기록 |
|---|---|
| 답을 냈는가 | 예 / 아니오 / 회피(추정임을 밝힘) |
| 숫자가 있는가 | 예 / 아니오 |
| 출처 | 1차 데이터 / 기사 재인용 / 없음 |
| 시점 | 데이터 기준일. 없으면 "불명" |
| 검증 결과 | 일치 / 불일치 / **확인 불가** |
| 소요 시간 | 벽시계 |

## 아직 정하지 않은 것 (실행 전에 소유자와 결정)

**소요 시간을 승패에 넣는가.** B 는 게이트웨이 전파로 7~10분을 기다리고 A 는 30초다.
"정확하지만 느림"을 패배로 볼지 별도 축으로 볼지에 따라 결론이 달라진다.
(멈춰 둔 다른 지도의 "N분" 질문과 같은 뿌리다.)

## 판정 기준 (미리 고정)

- **계급이 있다**: 질문의 1/3 이상에서 A 가 답을 못 내거나, 냈지만 검증에서 불일치·시점
  미상이다. 그리고 그 실패에 **패턴**이 있다(최신성 / 교차 / 롱테일 중 무엇인지 말할 수 있다).
- **계급이 좁다**: 실패가 있지만 흩어져 있고 패턴이 없다 → 특정 상황용 유틸리티다.
  일반화에 큰 투자를 할 근거가 없다.
- **계급이 없다**: A 가 거의 다 이긴다 → 접근 자동화는 풀 가치가 있는 문제가 아니다.
  지도를 다른 목적지로 다시 그린다(예: 카탈로그·명세 surface 가 진짜 가치였다).

## 왜 이게 첫 번째인가

싸고(몇 시간), 이 지도에서 가장 비싼 티켓(`02`)을 죽일 수 있다. 그리고 실패 패턴이
seed set(`08`)을 고르는 근거가 된다 — 어떤 데이터가 웹으로 안 나오는지 알아야 어떤 문을
열지 정할 수 있다.

## 주의

**"웹이 이긴다"가 나올 가능성을 진지하게 받아들일 것.** 그 답도 유효한 산출이다.
유리한 결과가 나올 때까지 질문을 바꾸거나 베이스라인을 약화시키지 않는다.
