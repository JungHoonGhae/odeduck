# apply 리팩터링 라이브 검증

Type: task
Status: open

## Question

`feat/apply-probe` 브랜치에 라이브 검증이 끝나지 않은 `apply` 리팩터링이 서 있다.
일반화 실험이 이 코드 위에서 돌기 때문에, 이게 확실해지기 전에는 실험 결과를 해석할 수 없다.

머지해도 되는가?

## 배경

`apply` 의 네비게이션과 폼 채우기를 `onApplyForm` 으로 추출해, 프로브(`ProbeApplyForm`)가
**같은 경로·같은 셀렉터**를 쓰게 했다. 다른 경로를 타는 프로브는 아무것도 증명하지 못한다.

리팩터링 중 실제 결함이 하나 드러났다: 기존 `apply` 는 폼 구조 검증을 `#reqForm` 존재
여부 하나로만 했고, 목적분류 라디오나 이용동의 체크박스가 사라져도 실계정에 `fn_save()` 를
호출했다. 지금은 5개 요소를 모두 확인하고 하나라도 없으면 제출을 거부한다.

단위 테스트는 통과하지만 **실제 포털을 상대로는 한 번도 돌지 않았다.**

## 해야 할 일 (HITL — 로그인 필요)

1. `gongctl login`
2. `gongctl doctor` — apply 행이 `ok` 인지. 카나리 pk 가 이미 신청됐으면 `--apply-pk` 로 교체
3. 실제 활용신청 1건 수행(되돌릴 수 없음 — 사용자 동의 전제)
4. 통과 시 머지·릴리즈, 실패 시 원인 기록

## 좋은 답의 모양

doctor 의 apply 행 + 실제 신청 결과 + 머지 여부. 실패했다면 어느 단계에서 깨졌는지.
